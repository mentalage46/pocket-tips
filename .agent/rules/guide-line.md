# Pocket Tips

- 모든 문서는 `docs/` 아래에 둔다. 루트 `README.md`는 뷰어 사용법만 다루고, 문서 목차는 `docs/README.md`가 담당한다.

- 폴더 내의 md 파일 추가 될 때마다 각 폴더의 README 파일에 해당 링크 추가

- `docs/README.md` 또한 해당 링크 및 설명 추가

- 문서를 추가·이동·삭제한 뒤에는 `npm run build`로 `manifest.json`을 갱신하고 `npm run check-links`로 링크와 앵커를 확인한다.

## 사실 검증 플로우

문서의 **개념 설명**은 모델 지식으로 쓸 수 있지만, 아래 **사실 항목**은 작성 시점에 1차 출처로 확인한다.

| 사실 항목 | 예 |
| --- | --- |
| 도구·제품·라이브러리의 이름, 현재 상태, 기능 | 서비스 종료, 후속 제품, 지원 여부 |
| 코드 예시의 API 이름, import 경로, 패키지명 | SDK 클래스·메서드, 설정 파일 형식 |
| 명령, 포트, 플래그, 설정 키 | CLI 사용법, 기본 포트 |
| 수치 | 가격 비율, 한도, 메모리 계산, 기준값(WCAG 등) |
| 표준·목록의 항목과 순서 | OWASP 목록, 명세 버전, 폐기 예정 기능 |

절차:

1. 문서 초안을 쓰면서 사실 항목을 표시해 둔다.
2. 공식 문서·저장소·명세(1차 출처)를 WebFetch로 읽고, 없으면 WebSearch 후 1차 출처로 들어가 확인한다. 라이브러리 API는 context7도 활용한다.
3. 틀린 항목은 고치고, 확인하지 못한 항목은 본문에 "(미확인)" 또는 "확인 시점 기준"으로 표시한다.
4. 사실 항목이 있는 문서 끝에 `## 참고 자료` 섹션을 두고 확인한 1차 출처 링크와 `확인일: YYYY-MM-DD`를 적는다. 일부만 확인했으면 어느 항목을 확인했는지 괄호로 적는다.
5. 도구 목록·버전·가격이 중심인 문서는 6개월이 지나면 재확인 대상으로 본다.

검증하지 않는 것: 일반 원칙·패턴 설명, 저자의 경험칙(단, 경험칙임을 표시). 링크 검사와 뷰어 렌더링 확인은 형식 검사이며 사실 검증을 대신하지 않는다.
