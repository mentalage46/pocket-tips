# 레지스터와 비트 연산

하드웨어 레지스터는 장치의 설정·상태·데이터를 표현합니다. MCU 내부 레지스터는 메모리 주소로, 외부 모듈의 레지스터는 I2C·SPI 등의 명령으로 접근하는 경우가 많습니다.

먼저 알면 좋은 개념: [MSB/LSB·엔디언·W1C](../glossary/firmware.md#데이터와-레지스터), [레지스터 접근의 부작용](../background/register-side-effects.md)

## 2진수와 16진수

```text
10진수 10 = 2진수 00001010 = 16진수 0x0A
10진수 255 = 2진수 11111111 = 16진수 0xFF

8비트 값의 비트 위치: 7 6 5 4 3 2 1 0
비트 0이 최하위 비트(LSB)
```

16진수 한 자리는 4비트를 표현합니다. 따라서 8비트 값은 두 자리, 16비트 값은 네 자리로 표현할 수 있습니다.

## 마스크로 비트 다루기

아래 C 예제는 **일반 변수**에서의 연산입니다. 실제 하드웨어 레지스터에 그대로 적용하기 전에 레지스터의 접근 규칙을 확인해야 합니다.

```c
unsigned int value = 0x00u;
const unsigned int enable_mask = 1u << 3;

value |= enable_mask;          // 비트 3을 1로 설정: 0x08
unsigned int enabled = (value & enable_mask) != 0u;
value &= ~enable_mask;         // 비트 3을 0으로 해제: 0x00
value ^= enable_mask;          // 비트 3을 반전: 0x08
```

| 연산 | 의미 | 용도 |
| --- | --- | --- |
| `&` | 비트 AND | 특정 비트 검사, 마스크 적용 |
| `\|` | 비트 OR | 특정 비트 설정 |
| `^` | 비트 XOR | 특정 비트 반전 |
| `~` | 비트 NOT | 마스크 반전 |
| `<<`, `>>` | 시프트 | 비트 위치 이동, 필드 추출 |

논리 연산자 `&&`, `||`와 비트 연산자 `&`, `|`는 다릅니다. 시프트에는 부호 없는 값을 우선 사용하고 이동량이 자료형의 비트 폭보다 작도록 제한합니다.

## 여러 비트로 이루어진 필드

설정값이 비트 6:4에 들어간다면 기존 필드를 지우고 새 값을 넣습니다.

```c
unsigned int config = 0x80u;
const unsigned int mode_mask = 0x07u << 4;
const unsigned int mode = 5u;  // 유효 범위 0~7

config = (config & ~mode_mask) | ((mode << 4) & mode_mask);
// config = 0xD0: 비트 7 보존, 비트 6:4에 101 저장

unsigned int read_mode = (config & mode_mask) >> 4;  // 5
```

마스크는 범위를 벗어난 설정을 정상화하는 검증 수단이 아닙니다. 설정값의 유효 범위는 별도로 확인합니다.

## 바이트 순서와 부호

MSB 우선으로 받은 두 바이트 `high`, `low`를 합치는 개념은 다음과 같습니다.

```text
raw_unsigned = high × 256 + low

16비트 2의 보수 값이면:
    raw_signed = raw_unsigned
    raw_unsigned >= 32768 이면 raw_signed -= 65536
```

**엔디언**은 여러 바이트로 된 값을 메모리에 배치하는 순서입니다. 전송 바이트 순서와 CPU 메모리의 엔디언은 별개입니다. 변환 중 오버플로가 나지 않도록 충분히 넓은 자료형을 사용합니다. 유효 데이터가 12비트 등으로 잘려 있으면 데이터 정렬과 부호 확장 규칙을 따로 적용합니다.

## 실제 레지스터에서 주의할 점

- **RO / WO / RW**: 읽기 전용, 쓰기 전용, 읽기·쓰기 가능 여부를 확인합니다.
- **W1C**: 1을 쓰면 지워집니다. `reg |= mask`는 다른 상태 비트까지 지울 수 있습니다.
- **Read-to-clear**: 읽기 자체가 상태를 지웁니다. 디버거의 자동 조회도 영향을 줄 수 있습니다.
- **예약 비트**: 문서가 요구하는 값을 유지합니다. 무조건 0을 쓰거나 기존 값을 보존한다고 가정하지 않습니다.
- **Read-modify-write**: 읽기와 쓰기 사이에 인터럽트나 하드웨어가 상태를 바꿀 수 있습니다. 전용 SET/CLEAR 레지스터나 적절한 동기화를 사용합니다.
- **volatile**: 메모리 매핑 I/O 접근을 컴파일러가 일반 변수처럼 생략하지 않도록 하는 데 쓰이지만, 원자성·상호 배제·모든 종류의 메모리 순서를 보장하지는 않습니다. 플랫폼이 제공하는 접근 수단을 따릅니다.
