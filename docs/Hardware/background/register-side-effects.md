# 레지스터 접근의 부작용

먼저 알면 좋은 개념: [레지스터와 비트 연산](../firmware/registers-and-bitwise.md), [데이터와 레지스터 용어](../glossary/firmware.md#데이터와-레지스터)

## 저장된 숫자를 읽고 쓰는 것 이상의 의미

일반 변수는 보통 읽어도 값이 유지되고 쓰면 그 값이 저장됩니다. 하드웨어 레지스터는 접근 자체가 동작을 일으킬 수 있습니다. 읽으면 이벤트 상태가 지워지거나, 쓰면 측정이 시작될 수 있습니다.

따라서 주소와 비트 위치 외에도 읽기·쓰기 권한, 초기값, 부작용, 예약 비트 규칙을 확인해야 합니다.

## W1C에서 비트 OR가 위험한 이유

다음은 **하위 두 비트가 모두 W1C이고 나머지 비트에 0 쓰기가 허용된 가상 레지스터**입니다. 실제 제품에서는 비트별 접근 속성이 섞일 수 있습니다.

```text
현재 상태:       00000011  ← 이벤트 0과 1이 모두 발생
지우려는 상태:   비트 0만

status |= 0b01의 읽기-수정-쓰기:
  읽음:         00000011
  OR 결과:      00000011
  씀:           00000011  → 비트 0과 1 모두 지워짐

이 가상 레지스터에 00000001을 직접 쓰면:
  비트 0만 지워지고 비트 1은 유지
```

W1C는 “1을 저장하라”가 아니라 “이 비트를 지워라”라는 명령으로 해석됩니다. 일반 변수에서 유용한 `|=`가 여기서는 의도하지 않은 이벤트까지 지울 수 있습니다.

## 읽기에도 부작용이 있을 수 있다

Read-to-clear 레지스터는 읽는 순간 상태가 지워집니다. 로그 출력을 위해 한 번 읽고 실제 처리에서 다시 읽으면 두 번째에는 이벤트가 없을 수 있습니다. 디버거의 자동 갱신 창도 같은 문제를 만들 수 있습니다.

필요한 값을 한 번 읽어 보관하고 그 복사본으로 여러 판단을 하는 방법을 검토합니다. 다만 읽기 순서나 묶음 읽기 규칙이 있는 장치는 해당 절차가 우선입니다.

## 읽기와 쓰기 사이에 누가 값을 바꿀까

```text
일반 실행 흐름: 설정 레지스터에서 00000000을 읽음
인터럽트:      비트 1을 켜서 00000010을 기록
일반 실행 흐름: 앞서 읽은 값에 비트 0을 켜 00000001을 기록
결과:          인터럽트가 켠 비트 1이 사라짐
```

이것이 읽기-수정-쓰기 사이의 경쟁 문제입니다. 전용 SET/CLEAR 레지스터가 있으면 해당 기능을 활용할 수 있습니다. 소프트웨어끼리의 접근은 플랫폼에 맞는 임계 구역 등으로 보호할 수 있지만, CPU 인터럽트를 막아도 주변장치 자체나 다른 코어의 동작까지 모두 멈추는 것은 아닙니다.

## volatile이 해결하는 범위

`volatile`은 하드웨어 접근을 일반 변수 접근처럼 생략하지 않도록 하는 데 사용합니다. 그러나 읽기-수정-쓰기 전체를 하나의 원자적 동작으로 만들거나 다른 실행 흐름을 차단하지 않습니다. 장치 메모리의 접근 순서와 폭에도 제약이 있을 수 있으므로 플랫폼이 제공하는 접근 함수를 따릅니다.

실제 레지스터에 적용하기 전에는 해당 비트의 접근 속성과 제조사 권장 절차를 먼저 확인합니다. 위 예제는 특정 MCU나 SDK에서 바로 실행하는 코드가 아닙니다.
