# SPI

SPI는 클록에 맞춰 데이터를 이동하고 칩 선택 신호로 대상 장치를 지정하는 동기식 직렬 통신 방식입니다.

먼저 알면 좋은 개념: [SPI 신호 이름·CPOL/CPHA·더미 클록](../glossary/communication.md#spi), [에지·셋업·홀드 시간](../glossary/signals.md#시간과-파형)

## 주요 신호

| 신호 | 방향과 역할 |
| --- | --- |
| SCLK / SCK | 컨트롤러가 생성하는 클록 |
| MOSI / COPI | 컨트롤러 → 주변장치 데이터 |
| MISO / CIPO | 주변장치 → 컨트롤러 데이터 |
| CS / SS | 대상 장치 선택, 흔히 active-low |
| GND | 비절연 연결에서 신호 기준 공유 |

장치에 따라 데이터선 하나만 쓰거나 별도 D/C, RESET, BUSY 핀이 필요할 수 있습니다. 핀 이름만으로 전체 프로토콜을 추측하지 않습니다.

## 클록 모드

CPOL은 유휴 클록 레벨, CPHA는 데이터를 샘플링하는 에지를 결정합니다. **에지**는 신호가 LOW→HIGH 또는 HIGH→LOW로 바뀌는 순간이고, 여기서 **샘플링**은 그 시점의 데이터 값을 읽는 것입니다.

| 모드 | CPOL | CPHA | 샘플링 에지 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 첫 번째 에지: 상승 |
| 1 | 0 | 1 | 두 번째 에지: 하강 |
| 2 | 1 | 0 | 첫 번째 에지: 하강 |
| 3 | 1 | 1 | 두 번째 에지: 상승 |

모드뿐 아니라 최대 클록, 비트 순서(MSB/LSB first), 워드 길이도 일치해야 합니다. 배선과 레벨 시프터 때문에 데이터시트의 최대 속도보다 낮게 동작시켜야 할 수 있습니다.

## 읽기 동작

일반적인 4선식 SPI는 송신과 수신이 동시에 일어납니다. 수신할 때도 컨트롤러가 클록을 만들도록 더미 바이트를 송신할 수 있습니다.

```text
CS 활성화
읽기 명령과 주소 전송
장치가 요구하는 더미 클록 제공
데이터를 받을 만큼 전송을 계속하며 수신
CS 비활성화
```

명령 형식, 더미 사이클 수, 주소 길이, CS 유지 시간은 장치마다 다릅니다. 일부 장치는 CS가 해제되면 명령 프레임이 끝나므로, 주소 전송과 데이터 수신 사이에 CS가 끊기지 않게 해야 합니다.

## 여러 장치 연결

SCLK와 데이터선을 공유하고 장치마다 별도 CS를 배정하는 구성이 흔합니다.

- 동시에 하나의 장치만 선택합니다.
- 선택되지 않은 장치가 MISO를 고임피던스로 해제하는지 확인합니다.
- 장치마다 모드·속도가 다르면 트랜잭션 전에 해당 설정을 적용합니다.
- 리셋 중에도 CS가 비활성 상태를 유지하도록 필요하면 풀업을 둡니다.

SPI에는 I2C와 같은 공통 주소·ACK 체계가 없습니다. 데이터 수신이 끝났다고 장치가 올바르게 응답했다는 뜻은 아닙니다. 식별값·상태·CRC 등 장치가 제공하는 수단으로 확인합니다.

## UART·I2C·SPI 비교

| 구분 | UART | I2C | SPI |
| --- | --- | --- | --- |
| 기본 신호선 | TX, RX | SDA, SCL | SCLK, MOSI, MISO, CS |
| 클록선 | 없음 | 있음 | 있음 |
| 대상 선택 | 보통 점대점 연결 | 버스 주소 | CS |
| 흔한 용도 | 로그, 통신 모듈 | 센서, 설정용 주변장치 | 디스플레이, 메모리, 빠른 주변장치 |

위 신호선 수에는 GND와 전원, 선택적 제어선이 포함되지 않습니다. 실제 속도와 거리 제한은 장치 및 전기적 구성에 따라 달라집니다.
