# I2C

I2C는 SDA(데이터)와 SCL(클록)을 공유하고 주소로 장치를 선택하는 통신 방식입니다. 센서나 소형 주변장치 연결에 자주 사용합니다.

먼저 알면 좋은 개념: [I2C·ACK/NACK·클록 스트레칭](../glossary/communication.md#i2c), [풀업과 출력 구동](../background/pullups-and-drive.md), [정전용량과 상승 시간](../background/capacitance-and-timing.md)

## 배선과 풀업

```text
호환되는 논리 전원 ── 풀업 저항 ── SDA ── 각 장치 SDA
호환되는 논리 전원 ── 풀업 저항 ── SCL ── 각 장치 SCL
공통 GND ─────────────────────── 각 장치 GND
```

일반적인 I2C의 SDA/SCL은 오픈드레인 방식이므로 두 선에 풀업이 필요합니다. **오픈드레인**은 LOW로 당기거나 출력을 해제하는 방식이며, HIGH는 풀업이 만듭니다.

> 용어 풀이: **버스 정전용량**은 공유 배선과 연결된 핀 등이 가진 정전용량을 합쳐 본 값입니다. 이를 충전하는 데 시간이 걸려 신호 상승이 느려집니다. **싱크 전류**는 LOW로 당기는 출력 핀이 외부 회로에서 받아들이는 전류입니다.

- 풀업이 너무 크면 상승이 느려집니다.
- 너무 작으면 LOW를 구동하는 장치가 감당해야 할 전류가 커집니다.
- 저항 선택은 버스 정전용량, 속도, 장치의 싱크 전류 능력에 따라 달라집니다.
- 4.7kΩ은 흔한 출발점일 뿐 항상 적합하지는 않습니다.
- 여러 모듈의 내장 풀업은 병렬 연결됩니다. 4.7kΩ 두 개의 합성 저항은 2.35kΩ입니다.

풀업 전압은 모든 장치와 호환되어야 합니다. 짧은 배선과 낮은 속도로 먼저 통신을 확인합니다.

## 주소와 ACK/NACK

일반적인 7비트 주소에서 R/W 비트는 주소 자체에 포함되지 않습니다.

```text
7비트 주소가 0x48인 가상의 장치:
버스에 전송되는 쓰기 주소 바이트 = (0x48 << 1) | 0 = 0x90
버스에 전송되는 읽기 주소 바이트 = (0x48 << 1) | 1 = 0x91
```

API가 7비트 주소를 요구하는지 시프트된 주소를 요구하는지는 사용 환경의 문서를 확인합니다.

수신자는 각 바이트 뒤에 ACK 또는 NACK를 보냅니다. 주소 단계의 NACK는 주소 오류·배선·전원·준비 시간 문제일 수 있습니다. 읽기의 마지막 바이트 뒤에 컨트롤러가 보내는 NACK는 정상적인 종료 동작입니다.

## 레지스터 읽기의 전형적인 흐름

다음은 레지스터 주소를 먼저 쓰는 장치의 예이며, 모든 장치가 이 방식을 쓰는 것은 아닙니다.

```text
START
주소 + Write → ACK
레지스터 주소 → ACK
Repeated START
주소 + Read → ACK
데이터 수신 → 더 읽으면 ACK, 마지막이면 NACK
STOP
```

레지스터 주소 길이, 자동 주소 증가, repeated START 요구 여부는 데이터시트를 따릅니다.

## 장치가 여러 개일 때

주소가 다르면 같은 버스를 공유할 수 있습니다. 주소가 고정된 동일 장치 두 개는 주소 변경 핀, 별도 버스, I2C 멀티플렉서 등의 방법이 필요합니다.

주소 스캔에서 응답이 있어도 모델이나 정상 측정을 보장하지는 않습니다. 가능하면 식별 레지스터와 상태 레지스터를 확인합니다. 주소 스캔도 실제 트랜잭션을 보내므로, 연결된 장치가 해당 접근에 민감한지 확인합니다.

## 점검 항목

- SDA/SCL의 유휴 상태가 HIGH인가?
- 풀업이 있으며 연결 전압과 합성 저항이 적절한가?
- 모든 장치가 선택한 속도를 지원하는가?
- 클록 스트레칭이 필요한 장치를 컨트롤러가 지원하는가?
- 통신에 타임아웃이 있으며, 버스가 LOW에 고정된 경우의 복구 절차가 있는가?
