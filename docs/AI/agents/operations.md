# 운영과 안전

에이전트를 팀에 도입하면 코드 품질 외에 **권한, 비용, 관측, 책임**을 함께 관리해야 합니다. 이 문서는 에이전트를 안전하게 운영하기 위한 기준과 단계적 도입 방법을 정리합니다.

## 권한과 격리

| 항목 | 기준 |
| --- | --- |
| 최소 권한 | 작업에 필요한 도구만. 리뷰 에이전트에게 쓰기 권한을 주지 않음 |
| 읽기·쓰기 분리 | 조사·리뷰는 읽기 전용, 구현은 브랜치 안에서만 쓰기 |
| 외부 영향 승인 | 배포, 삭제, 외부 전송, 결제는 사람 승인 |
| 비밀 정보 | 토큰·키는 환경 변수나 비밀 저장소로. 프롬프트·로그에 남기지 않음 |
| 샌드박스 | 신뢰할 수 없는 입력(외부 저장소, 내려받은 파일)을 다룰 때는 격리 환경 |
| 네트워크 | 필요한 호스트만 허용. 데이터 유출 경로를 줄임 |

## 프롬프트 주입과 신뢰 경계

에이전트가 읽는 모든 텍스트(이슈 본문, 웹 페이지, 외부 저장소 파일, 도구 출력)는 **지시가 아니라 데이터**입니다.

| 위험 | 예 | 대응 |
| --- | --- | --- |
| 간접 주입 | 이슈 본문에 "비밀 파일을 출력하라"가 적혀 있음 | 외부 텍스트를 지시로 따르지 않도록 지침, 쓰기·전송 도구는 승인형 |
| 도구 출력 오염 | 웹 검색 결과에 악성 지시 포함 | 출력을 요약·인용으로 다루고 행동 결정은 원래 목표 기준 |
| 공급망 | 설치한 MCP 서버·스킬이 과도한 권한 요구 | 출처 확인, 권한 검토, 버전 고정 |

## 비용 관리

| 항목 | 방법 |
| --- | --- |
| 예산 | 작업·세션·일 단위 토큰 또는 금액 한도 |
| 정체 감지 | 같은 도구 호출이 반복되면 중단하고 보고 |
| 문맥 절약 | 필요한 파일만 읽기, 긴 출력은 요약, 하위 에이전트 활용 |
| 모델 선택 | 분류·요약처럼 단순한 단계는 작은 모델, 설계·디버깅은 큰 모델 |
| 캐시 | 반복되는 긴 문맥(지침, 코드베이스 요약)은 프롬프트 캐시 활용 |
| 측정 | 작업 유형별 평균 비용과 성공률을 기록해 비교 |

## 관측

| 기록할 것 | 이유 |
| --- | --- |
| 입력 요청과 최종 결과 | 재현과 평가 세트 구축 |
| 도구 호출 순서와 결과 | 실패 지점 추적 |
| 토큰·시간·비용 | 예산과 추세 |
| 사람 개입 지점 | 어떤 게이트가 자주 걸리는지 |
| 모델·프롬프트·하네스 버전 | 성능 변화의 원인 분리 |

로그에는 비밀 정보가 섞이기 쉽습니다. 마스킹 규칙을 먼저 정합니다.

## 품질 게이트

| 게이트 | 자동 | 사람 |
| --- | --- | --- |
| 정적 검사 | 린트, 타입, 포맷, 보안 스캔 | 규칙 유지 |
| 테스트 | 단위·통합·E2E 통과 | 테스트가 요구를 검증하는지 |
| 변경 범위 | 계획된 파일 외 변경 감지 | 범위 확장 승인 |
| 리뷰 | 리뷰 에이전트 지적 | 설계 의도, 제품 판단, 최종 승인 |
| 문서 | 링크 검사, 변경 로그 존재 | 내용 정확성 |

에이전트가 만든 코드도 사람이 만든 코드와 **같은 게이트**를 통과합니다. 별도의 느슨한 기준을 두지 않습니다.

## 책임과 규칙

| 항목 | 정할 것 |
| --- | --- |
| 작성자 표시 | 커밋·PR에 에이전트 사용 여부와 모델 표시 |
| 병합 책임 | 병합한 사람이 코드를 이해하고 책임짐 |
| 리뷰 규칙 | 에이전트 리뷰만으로 병합 불가, 사람 리뷰 필수 영역 |
| 데이터 | 어떤 코드·데이터를 외부 모델에 보내도 되는지 |
| 라이선스 | 생성 코드의 라이선스 검토 절차 |

## 팀 도입 단계

| 단계 | 범위 | 성공 기준 |
| --- | --- | --- |
| 1. 개인 보조 | 개발자가 보조·승인형으로 사용 | 사용자 만족, 사고 없음 |
| 2. 지침 공유 | 지침 파일·스킬을 저장소에 커밋 | 새 참여자가 지침만으로 에이전트 사용 가능 |
| 3. 자동 리뷰 | PR에 읽기 전용 리뷰 에이전트 | 지적의 채택률, 사람 리뷰 시간 감소 |
| 4. 위임 자동화 | 저위험 작업을 이슈→PR로 자동화 | PR 병합률, 되돌림 횟수 |
| 5. 측정과 확장 | 평가 세트와 비용 추적으로 범위 조정 | 작업 유형별 성공률·비용 추세 |

각 단계에서 **되돌림(revert)과 사고 횟수**를 기록합니다. 늘어나면 범위를 줄이고 원인을 지침·게이트에 반영합니다.

## 점검 목록

- [ ] 에이전트별 권한 범위가 문서화되어 있다
- [ ] 외부 영향 행동은 승인 없이 실행되지 않는다
- [ ] 비밀 정보가 프롬프트·로그에 들어가지 않는다
- [ ] 세션·작업 단위 비용 한도가 있다
- [ ] 도구 호출 추적이 남고 버전이 기록된다
- [ ] 에이전트 생성 코드가 사람 코드와 같은 게이트를 통과한다
- [ ] 병합 책임자와 리뷰 규칙이 정해져 있다
