# Agents

**AI 에이전트(Agent)**는 목표를 받아 스스로 관찰·판단·행동을 반복하면서 작업을 진행하는 시스템입니다. 이 섹션은 에이전트를 소프트웨어 개발 과정에 적용하는 방법을 다룹니다. PM, 아키텍트, 개발자, 리뷰어, QA, 운영 같은 역할을 에이전트가 어떻게 나눠 맡는지, 어떤 워크플로와 도구를 쓰는지, 팀의 지식을 에이전트가 쓸 수 있는 형태로 어떻게 쌓는지 정리합니다.

하네스가 "에이전트를 어떻게 실행하고 측정하는가"라면, 이 섹션은 "에이전트에게 어떤 일을 어떤 방식으로 맡기는가"에 가깝습니다.

## 어디까지가 에이전트인가

| 형태 | 다음 행동을 정하는 주체 | 예 |
| --- | --- | --- |
| 단일 호출 | 사람 | 함수 하나 작성 요청, 커밋 메시지 생성 |
| 워크플로 | 미리 짠 코드 | 이슈 생성 시 라벨 분류 → 담당자 제안 |
| 에이전트 | 모델이 관찰 결과를 보고 결정 | 테스트 실패 원인을 찾아 수정하고 다시 실행 |
| 멀티 에이전트 | 여러 에이전트가 역할을 나눠 결정 | 계획 담당, 구현 담당, 리뷰 담당이 순서대로 작업 |

경계는 제품마다 다릅니다. 비교할 때는 이름보다 **무엇을 관찰하고, 무엇을 스스로 결정하며, 어디서 사람이 개입하는지**를 봅니다.

## 먼저 기억할 것

- 에이전트는 사람을 대체하는 역할이 아니라 **역할의 일부 작업**을 맡습니다. 결정의 책임은 사람에게 남습니다.
- 잘 되는 적용은 입력(요구사항, 코드, 테스트)과 완료 기준이 분명한 작업에서 시작합니다.
- 에이전트가 읽을 수 있는 문서가 곧 에이전트의 실력입니다. 지식을 쌓는 일이 프롬프트를 다듬는 일보다 오래 남습니다.
- 자동화 범위를 넓히기 전에 작은 범위에서 성공률과 비용을 측정합니다.
