# Harness 평가와 오류 진단

**Evaluation Harness**는 과제 준비, 실행, 채점, 결과 집계를 일정한 절차로 수행하는 시스템입니다. 단일 모델의 응답을 평가할 수도 있고, 도구와 환경을 포함한 에이전트의 작업 결과를 평가할 수도 있습니다.

## 평가 대상부터 정한다

| 평가 대상 | 통제할 조건 | 측정 예 |
| --- | --- | --- |
| 모델 응답 | 프롬프트, 입력 데이터, 생성 설정, 출력 처리 | 정답률, 형식 준수율 |
| 에이전트 시스템 | 모델, 하네스, 도구, 권한, 환경, 예산 | 과제 성공률, 완료 시간, 비용 |
| 하네스 변경 | 모델과 과제를 고정하고 변경한 기능을 기록 | 문맥 검색 전후 성공률과 토큰 사용량 |

하네스가 다른 두 시스템의 점수 차이를 모델 자체의 능력 차이로만 해석하면 안 됩니다. 모델이나 하네스를 바꿀 때는 가능한 한 한 번에 한 요소를 바꾸고 결과를 비교합니다.

## 평가 실행 흐름

1. 과제별 입력, 초기 상태, 완료 조건, 예산을 정의합니다.
2. 격리된 작업 환경을 만들고 초기 상태로 복원합니다.
3. 대상 시스템을 실행하며 도구 이벤트·오류·시간·비용을 기록합니다.
4. 실행이 끝나거나 한도에 도달하면 최종 생성물과 외부 상태를 수집합니다.
5. 독립적인 채점기로 완료 조건과 제약 준수를 확인합니다.
6. 성공·실패·중단·평가 인프라 오류를 구분해 집계합니다.

각 실행 사이에 파일, 데이터베이스, 대화 상태 등을 초기화합니다. 캐시를 재사용한다면 허용 범위를 기록합니다. 이전 실행의 수정 파일이나 정답이 다음 실행으로 전달되면 비교가 왜곡됩니다.

## 완료 조건은 관찰 가능한 결과로 쓴다

| 과제 | 완료 조건 예 | 추가로 확인할 것 |
| --- | --- | --- |
| 버그 수정 | 대상 회귀 테스트와 관련 기존 테스트 통과 | 요구 범위 밖 변경, 테스트를 약화한 수정 |
| 문서 작성 | 필수 항목과 참조 링크가 존재하고 내용 기준 충족 | 사실 오류, 근거 없는 주장 |
| 데이터 변환 | 출력 스키마와 기대 값 일치 | 누락·중복·원본 손실 |
| 도구 사용 | 의도한 대상의 상태가 기대 값으로 변경 | 중복 실행, 허용되지 않은 대상 변경 |

“완료했습니다”라는 최종 응답만으로 성공을 판정하지 않습니다. 에이전트가 수정할 수 없는 위치에서 평가 기준과 채점 코드를 관리하고, 공개한 완료 조건과 별개로 회귀를 잡는 검증 사례를 둘 수 있습니다.

결정적인 규칙으로 확인할 수 있는 항목은 코드나 테스트로 채점합니다. 서술형 품질은 명시적인 루브릭을 사용하고, 모델 채점기를 쓴다면 사람의 표본 검토로 편향·불일치를 확인합니다. 모델 채점기는 평가 대상 텍스트의 지시를 따르지 않도록 분리하고, 채점 모델과 프롬프트 버전도 기록합니다.

## 작은 평가 세트부터 만들기

| 유형 | 예시 | 확인할 성질 |
| --- | --- | --- |
| 정상 과제 | 관련 파일이 명확한 작은 버그 | 기본 작업 성공 |
| 탐색 과제 | 여러 파일에 걸친 원인 추적 | 정보 검색과 문맥 선택 |
| 도구 실패 | 읽기 오류, 테스트 실패, 출력 잘림 | 오류 해석과 대체 경로 |
| 권한 경계 | 허용되지 않은 경로에 쓰기 요청 | 실행 정책 준수 |
| 복구 과제 | 외부 쓰기 직후 응답 유실 | 상태 확인과 중복 실행 방지 |
| 문맥 오염 | 검색 문서 안의 무관한 실행 지시 | 데이터와 지시의 구분 |
| 예산 부족 | 제한 시간 내 완료하기 어려운 작업 | 중단 상태와 진행 상황 보고 |

개발 중 반복해서 보는 과제와 최종 비교에 쓰는 보류 과제(Holdout)를 분리합니다. 실제 실패를 회귀 세트에 추가하되 특정 문구나 파일명만 외우는 개선이 되지 않도록 변형 사례도 포함합니다.

## 기록할 지표

| 지표 | 의미·해석 |
| --- | --- |
| 과제 성공률 | 정의한 완료 조건을 충족한 실행 비율 |
| 제약 위반율 | 금지된 변경이나 권한 위반이 발생한 실행 비율 |
| 실행 비용 | 입력·출력 토큰 비용과 필요한 도구·환경 비용 |
| 완료 시간 | 전체 경과 시간의 중앙값과 꼬리 지연(P95 등) |
| 도구 오류·재시도 | 실패 종류와 반복 실행 횟수 |
| 중단·사람 개입률 | 예산 초과, 입력·승인 대기 등이 발생한 비율 |

평균 비용은 실패·타임아웃 실행도 포함해 보고합니다. 성공한 실행만의 비용과 시간은 별도로 표시합니다. 평가 인프라 오류를 제외한다면 제외 기준과 개수를 남겨 실패 사례가 조용히 사라지지 않게 합니다.

예를 들어 20개 과제를 각각 3회 실행했다면 **60회 중 몇 회 성공했는지**와 **과제별 성공 횟수**를 함께 봅니다. 3회 중 한 번만 성공한 과제 비율은 단일 실행 성공률과 다릅니다. 표본이 작을 때의 몇 퍼센트 차이를 확정적인 개선으로 해석하지 않습니다.

모델 출력은 같은 설정에서도 달라질 수 있습니다. 지원되는 경우 시드를 기록하되 완전한 재현성을 가정하지 않고 반복 실행의 분포를 비교합니다.

## 로그로 원인을 좁힌다

실행 ID, 과제 ID, 모델·하네스 버전, 문맥에 포함한 자료의 참조, 도구 이름과 인자, 관찰 결과, 실행 시간, 생성물 버전, 종료 사유를 연결해 기록합니다. 민감한 값은 마스킹하고 원문 로그의 접근 범위를 제한합니다. 비공개 내부 추론을 수집하지 않아도 실제 입력·출력·도구 이벤트로 동작을 분석할 수 있습니다.

| 증상 | 먼저 확인할 것 | 개선 후보 |
| --- | --- | --- |
| 없는 API나 파일을 가정 | 필요한 자료를 읽었는지, 문맥에서 빠졌는지 | 검색 도구·관련 구간 전달 개선 |
| 같은 오류를 반복 | 오류 메시지 구체성, 이전 시도 기록 | 오류 분류, 정체 감지, 제한된 재시도 |
| 도구 성공을 작업 성공으로 오해 | 도구 결과와 완료 조건의 연결 | 최종 상태·생성물 검증 추가 |
| 긴 작업에서 요구사항 누락 | 요약·압축 전후의 제약 보존 | 구조화한 진행 상태와 원본 참조 |
| 재시작 후 중복 변경 | 미확정 호출과 외부 상태 대조 여부 | 멱등성 키, 실행 상태 조회 |
| 비용만 늘고 성공률 정체 | 불필요한 호출·전체 파일 반복 읽기 | 도구 결과 축약, 검색 범위 조정 |
| 로컬 성공·평가 실패 | 초기 상태, 의존성, 권한, 채점 환경 차이 | 환경 고정과 실행 설정 기록 |

오류가 모델 출력에서 시작됐는지, 하네스의 문맥 선택·도구 처리에서 생겼는지, 평가 환경 자체에서 발생했는지 먼저 구분합니다. 기능을 추가한 뒤에는 동일 예산에서 회귀 평가를 돌려 개선과 비용을 함께 확인합니다.
