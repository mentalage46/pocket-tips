# Prompting

프롬프트는 모델에 주는 지시·예시·자료의 묶음이며, 같은 모델에서 결과를 가장 크게 바꾸는 요소입니다. 이 폴더는 빠르게 쓰는 팁과 템플릿부터, 기법의 원리, 시스템 프롬프트 설계, 테스트와 반복 개선까지 다룹니다.

## 프롬프트가 할 수 있는 것과 없는 것

| 할 수 있는 것 | 할 수 없는 것 |
| --- | --- |
| 출력 형식·길이·언어 지정 | 모델이 모르는 사실을 알게 하기(→ RAG, 도구) |
| 작업 절차와 기준 제시 | 긴 산술·정밀 계산 보장(→ 코드 실행) |
| 예시로 스타일·판단 기준 전달 | 완전한 결정성(→ 출력 검증) |
| 모호한 요청의 해석 고정 | 프롬프트 주입 완전 차단(→ 권한·검증) |
| 거부·확인 규칙 설정 | 모델 능력 자체를 올리기(→ 모델 교체) |

## 먼저 기억할 것

- 프롬프트는 추측이 아니라 평가로 개선합니다. 대표 입력 수십 개와 기대 결과를 먼저 만듭니다.
- 지시는 짧고 구체적으로, 예시는 대표적으로, 자료는 필요한 만큼만 넣습니다.
- 모델이 틀렸다면 먼저 "지시가 모호했는가, 정보가 부족했는가, 능력 밖인가"를 구분합니다.
- 모델·버전이 바뀌면 같은 프롬프트의 결과도 바뀝니다. 프롬프트와 모델 ID를 함께 기록합니다.
