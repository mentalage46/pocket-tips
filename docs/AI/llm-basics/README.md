# LLM 기초와 API 활용

대규모 언어 모델(LLM)을 API로 호출해 소프트웨어에 넣을 때 알아야 할 기초를 정리합니다. 모델이 텍스트를 어떻게 만들고, 요청을 어떻게 구성하며, 출력을 어떻게 구조화하고, 비용과 지연을 어떻게 다루는지 다룹니다. [Harness](../harness/README.md)와 [Agents](../agents/README.md) 문서는 이 내용을 전제로 합니다.

## 학습 순서

| 순서 | 문서 | 알 수 있는 것 |
| --- | --- | --- |
| 1 | [모델의 동작 원리](./how-llms-work.md) | 토큰, 문맥 창, 생성 방식, 샘플링 파라미터, 한계와 모델 선택 |
| 2 | [API 호출 구조](./api-usage.md) | 메시지 역할, 멀티턴, 스트리밍, 오류와 재시도, 호출 래퍼 설계 |
| 3 | [구조화 출력과 도구 호출](./structured-output.md) | JSON 스키마 출력, 함수 호출 루프, 출력 검증 |
| 4 | [비용과 지연](./cost-and-latency.md) | 토큰 계산, 가격 구조, 프롬프트 캐싱, 배치, 지연 분해와 최적화 |

## 어디에 쓰이는가

| 사용 형태 | 예 | 핵심 관심사 |
| --- | --- | --- |
| 단일 호출 | 요약, 분류, 번역, 추출 | 프롬프트 설계, 구조화 출력, 비용 |
| 대화형 | 챗봇, 고객 지원, 사내 Q&A | 대화 기록 관리, 스트리밍, 안전 장치 |
| 검색 결합(RAG) | 문서 기반 답변, 코드 검색 | 검색 품질, 문맥 배치, 출처 표시 |
| 도구 사용·에이전트 | 코딩 에이전트, 업무 자동화 | 도구 계약, 실행 루프, 권한, 관측 |

위로 갈수록 단순하고 아래로 갈수록 통제할 요소가 많아집니다. 단일 호출로 해결되는 문제에 에이전트를 쓰면 비용과 실패 지점만 늘어납니다.

## 먼저 기억할 것

- 모델은 다음 토큰의 확률을 계산하는 함수이며, 문맥 창에 들어온 것만 알고 있습니다.
- 같은 입력이라도 샘플링 때문에 출력이 달라질 수 있으므로, 프로그램에서 쓰는 출력은 반드시 검증합니다.
- 비용과 지연은 토큰 수에 비례합니다. 입력 토큰을 줄이고 캐싱을 쓰는 것이 가장 효과가 큽니다.
- 모델 이름, 가격, 한도는 자주 바뀝니다. 수치는 공식 문서를 기준으로 확인하고 이 문서에서는 구조만 설명합니다.
- 공급자별 SDK는 세부 문법이 다르지만 메시지·도구·스트리밍·오류 처리의 개념은 거의 같습니다.
