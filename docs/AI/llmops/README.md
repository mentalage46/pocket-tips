# LLM 애플리케이션 운영

LLM을 호출하는 기능은 만들기는 쉽지만 **안정적으로 운영**하기는 어렵습니다. 모델 API는 외부 의존성이고, 출력은 비결정적이며, 비용은 사용량에 비례해 늘어납니다. 이 문서는 LLM 기능을 서비스로 운영할 때 필요한 아키텍처, 프롬프트 관리, 신뢰성, 관측과 비용 통제를 다룹니다.

## 학습 순서

| 순서 | 문서 | 알 수 있는 것 |
| --- | --- | --- |
| 1 | [아키텍처](./architecture.md) | LLM 계층 분리, 게이트웨이, 라우팅, 동기·비동기 처리, 배포 단위 |
| 2 | [프롬프트 관리](./prompt-management.md) | 프롬프트를 코드처럼: 템플릿, 버전, 리뷰, 배포, 롤백 |
| 3 | [신뢰성](./reliability.md) | 타임아웃, 재시도, 폴백, 회로 차단, 캐싱, 품질 저하 대응 |
| 4 | [관측과 비용](./observability-and-cost.md) | 추적, 지표, 로그, 비용 배분, 예산 통제, 알림 |

## 일반 서비스 운영과 다른 점

| 항목 | 일반 API 서비스 | LLM 기능 |
| --- | --- | --- |
| 응답 | 결정적, 스키마 보장 | 비결정적, 검증 필요 |
| 지연 | 수십 ms | 수백 ms~수십 초, 출력 길이에 비례 |
| 비용 | 요청 수 | 토큰 수. 긴 입력·출력이 비용을 좌우 |
| 장애 | 자체 인프라 | 공급자 장애·속도 제한·모델 변경 |
| 회귀 | 코드 변경 시 | 프롬프트·모델 버전·공급자 측 변경 시 |
| 테스트 | 단언 기반 | 평가 세트와 채점 기준 |

## 먼저 기억할 것

- LLM 호출은 한 모듈을 통해서만 나가게 하고, 그곳에서 재시도·로깅·비용 집계를 처리합니다.
- 프롬프트는 설정이 아니라 코드입니다. 버전을 붙이고 리뷰하고 평가 후 배포합니다.
- 공급자 장애와 속도 제한은 반드시 옵니다. 폴백 경로와 품질 저하 모드를 미리 정합니다.
- 비용은 기능·사용자·프롬프트 버전 단위로 나눠서 봐야 줄일 곳이 보입니다.
- 모델 버전은 고정하고, 교체는 평가 세트로 비교한 뒤 점진적으로 합니다.
