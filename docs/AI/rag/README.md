# RAG와 지식 검색

**RAG(Retrieval-Augmented Generation)**는 질문과 관련된 문서를 먼저 검색해 모델의 문맥에 넣고, 그 근거를 바탕으로 답을 생성하는 방식입니다. 모델이 모르는 사내 문서, 최신 정보, 개인 데이터를 다룰 때 가장 널리 쓰이는 구조이며, 품질의 대부분은 모델이 아니라 **검색**에서 결정됩니다.

## RAG가 해결하는 것과 못 하는 것

| 문제 | RAG로 해결 | 다른 수단 |
| --- | --- | --- |
| 모델이 사내·최신 정보를 모름 | 가능. 문서를 검색해 문맥에 제공 | 파인튜닝은 사실 주입에 비효율적 |
| 답변의 출처를 보여야 함 | 가능. 검색된 조각을 근거로 표시 | - |
| 문맥 창보다 자료가 큼 | 가능. 필요한 부분만 선택 | 자료가 작으면 전부 문맥에 넣는 것이 더 정확 |
| 말투·형식을 바꾸고 싶음 | 부적합 | 프롬프트, 파인튜닝 |
| 여러 문서를 집계·계산해야 함 | 단독으로는 약함 | 구조화 데이터 조회, 코드 실행 도구 |
| 자료 자체가 틀림 | 불가능. 틀린 근거로 답함 | 자료 품질 관리 |

## 먼저 기억할 것

- 답이 틀렸을 때 먼저 확인할 것은 프롬프트가 아니라 "올바른 조각이 검색되었는가"입니다.
- 청킹과 임베딩은 색인 시점에 결정되고, 바꾸려면 재색인이 필요합니다. 처음부터 평가 세트를 만들어 비교합니다.
- 키워드 검색과 벡터 검색은 서로 다른 질문에 강합니다. 실무에서는 둘을 합치는 하이브리드가 기본입니다.
- 검색된 조각은 사용자 입력과 같은 신뢰 수준의 데이터입니다. 조각 안의 지시를 따르지 않도록 프롬프트와 검증을 설계합니다.
- 자료가 수십 페이지 수준이면 검색 없이 문맥에 통째로 넣고 프롬프트 캐싱을 쓰는 편이 단순하고 정확할 수 있습니다.
