# 벡터 저장소

벡터 저장소는 임베딩 벡터를 저장하고 **가까운 벡터를 빠르게 찾는** 기능을 제공합니다. RAG에서는 벡터 검색뿐 아니라 키워드 검색, 메타데이터 필터, 갱신·삭제까지 함께 다루어야 하므로 선택 기준이 단순 검색 속도보다 넓습니다.

## 유사도와 인덱스

| 유사도 | 설명 | 비고 |
| --- | --- | --- |
| 코사인 | 방향의 유사성. 정규화된 벡터에서 내적과 동일 | 가장 흔한 기본값 |
| 내적(dot product) | 크기와 방향 모두 반영 | 모델이 내적 기준으로 학습된 경우 |
| 유클리드(L2) | 거리 | 일부 모델·라이브러리의 기본값 |

임베딩 모델이 권장하는 유사도를 그대로 씁니다.

| 인덱스 | 방식 | 특징 |
| --- | --- | --- |
| 정확 탐색(Flat) | 모든 벡터와 비교 | 정확, 수만 건까지는 충분히 빠름 |
| HNSW | 그래프 기반 근사 탐색 | 빠르고 정확도 높음, 메모리 사용 큼, 대부분의 기본값 |
| IVF | 클러스터로 나눈 뒤 일부만 탐색 | 메모리 효율, 재현율은 탐색 범위 설정에 의존 |
| 양자화(PQ 등) | 벡터를 압축 저장 | 대규모에서 비용 절감, 정확도 소폭 손실 |

근사 탐색(ANN)은 정확 탐색보다 빠르지만 일부 결과를 놓칠 수 있습니다. 수만 건 이하면 정확 탐색으로 시작하고, 지연이 문제될 때 ANN으로 바꿉니다.

## 저장소 선택

| 유형 | 예 | 장점 | 주의 |
| --- | --- | --- | --- |
| 기존 DB 확장 | PostgreSQL + pgvector | 운영·트랜잭션·권한을 기존 DB에서 처리 | 수백만 건 이상에서는 튜닝 필요 |
| 검색 엔진 | Elasticsearch, OpenSearch | 키워드와 벡터를 한 곳에서, 하이브리드에 유리 | 운영 복잡도 |
| 전용 벡터 DB | Qdrant, Milvus, Weaviate, Pinecone | 대규모·고성능, 필터 결합 최적화 | 데이터가 두 곳으로 분리, 동기화 필요 |
| 라이브러리 | FAISS, hnswlib | 가볍고 빠름, 프로토타입 | 영속성·갱신·필터는 직접 구현 |
| 내장형 | SQLite 확장, Chroma, LanceDB | 로컬·소규모·개인 도구에 적합 | 동시성·확장성 제한 |

| 결정 기준 | 질문 |
| --- | --- |
| 규모 | 청크 수가 수만, 수백만, 수억 중 어디인가 |
| 하이브리드 | 키워드 검색을 같은 저장소에서 할 수 있는가 |
| 필터 | 메타데이터 사전 필터를 지원하는가, 필터 후 결과 수가 보장되는가 |
| 갱신 | 문서 단위 삭제·재삽입이 쉬운가, 삭제가 즉시 반영되는가 |
| 운영 | 백업, 복제, 모니터링, 접근 제어를 기존 체계로 다룰 수 있는가 |
| 비용 | 메모리 상주 벡터 크기 = 청크 수 × 차원 × 4바이트(float32) |

처음에는 이미 운영 중인 DB의 벡터 확장으로 시작하고, 규모나 지연이 한계에 닿을 때 이전하는 것이 안전합니다.

## 메타데이터 필터링

```mermaid
flowchart LR
    Q[질의 벡터 + 필터 조건] --> F{필터 시점}
    F -->|사전 필터| A[조건에 맞는 벡터만 탐색] --> R1[결과 k개 보장]
    F -->|사후 필터| B[상위 k 탐색 후 조건 적용] --> R2[결과가 k보다 적을 수 있음]
```

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 사전 필터 | 결과 수 보장, 권한 필터에 필수 | 인덱스가 필터와 결합되어야 빠름 |
| 사후 필터 | 구현 단순 | 필터가 빡빡하면 결과가 비거나 부족 |
| 파티션 분리 | 테넌트·권한별 인덱스 분리 | 인덱스 수 증가 |

권한 필터는 반드시 사전 필터나 파티션 분리로 처리합니다. 사후 필터로 걸러낸 뒤 결과가 부족하면 k를 늘려 재탐색하는 로직이 필요해지고, 그 과정에서 누락이 생기기 쉽습니다.

## 운영

| 항목 | 내용 |
| --- | --- |
| 스키마 | 청크 ID, 문서 ID, 벡터, 본문, 메타데이터, 임베딩 모델 버전 |
| 재색인 | 새 컬렉션에 적재 → 평가 → 별칭(alias) 전환. 서비스 중단 없이 교체 |
| 삭제 | 원본 삭제와 함께 처리. 소프트 삭제 플래그를 필터에 포함하는 방법도 가능 |
| 백업 | 벡터는 원본 문서에서 재생성 가능하므로 원본과 메타데이터를 우선 보호 |
| 모니터링 | 검색 지연 p95, 인덱스 크기, 메모리, 재현율 샘플 검사 |
| 다중 테넌트 | 테넌트 ID를 필수 필터로 강제. 코드 경로 하나에서 누락되면 데이터 유출 |
