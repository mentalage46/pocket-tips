# MCP 서버와 도구 설계

**MCP(Model Context Protocol)**는 LLM 애플리케이션이 외부 데이터와 기능에 연결하는 방식을 표준화한 개방형 프로토콜입니다. 서버를 한 번 만들면 이를 지원하는 여러 클라이언트(코딩 에이전트, 데스크톱 앱, 자체 에이전트)에서 같은 도구를 쓸 수 있습니다. 이 문서는 MCP의 구조, 도구를 잘 설계하는 법, 서버를 직접 만들고 테스트·배포하는 절차를 다룹니다.

## 언제 MCP 서버를 만드는가

| 상황 | MCP가 적합 | 다른 수단 |
| --- | --- | --- |
| 여러 에이전트 제품에서 같은 사내 시스템을 쓰고 싶다 | 적합 | - |
| 코딩 에이전트에 이슈 트래커·문서·DB 조회를 붙이고 싶다 | 적합 | 공식·커뮤니티 서버가 있으면 그대로 사용 |
| 자체 에이전트 한 곳에서만 쓰는 함수 | 과함 | SDK의 도구 정의로 직접 연결 |
| 단순 파일 읽기·셸 실행 | 불필요 | 대부분의 에이전트가 내장 |
| 외부 공개 API를 에이전트에 노출 | 적합 | 단, API를 1:1로 감싸지 말고 작업 단위로 재설계 |

## 먼저 기억할 것

- MCP는 전송·메시지 규약입니다. 도구의 품질은 프로토콜이 아니라 설명·스키마·결과 형식에서 결정됩니다.
- 도구는 API 엔드포인트가 아니라 **모델이 수행할 작업** 단위로 설계합니다.
- 서버는 신뢰 경계입니다. 권한, 입력 검증, 비밀 관리는 서버 안에서 처리하고 모델에 맡기지 않습니다.
- 도구를 많이 노출할수록 모델의 선택 정확도가 떨어집니다. 적고 명확한 도구가 낫습니다.
- 공식 명세와 SDK는 계속 바뀝니다. 이 문서는 명세 2026-07-28과 그 시점의 SDK 기준이며, 전송 방식·인가·SDK API는 공식 문서로 현재 버전을 확인합니다.
