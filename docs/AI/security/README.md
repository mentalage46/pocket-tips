# AI 보안

LLM을 넣은 애플리케이션은 기존 웹 보안 위협에 더해 **모델이 입력을 지시로 해석한다**는 성질에서 오는 새로운 위협을 가집니다. 프롬프트 주입, 민감 정보 유출, 과도한 권한, 검증되지 않은 출력이 대표적입니다. 이 문서는 OWASP LLM Top 10을 기준으로 위협을 정리하고, 프롬프트 주입과 데이터·출력 보호를 자세히 다룹니다.

## 기존 보안과의 관계

| 기존 위협 | LLM 환경에서의 변형 |
| --- | --- |
| SQL 인젝션 | 모델이 생성한 쿼리를 그대로 실행 → 출력 검증 실패 |
| XSS | 모델 출력의 HTML·스크립트를 그대로 렌더링 |
| SSRF | 모델이 도구로 내부 URL 요청 |
| 권한 상승 | 모델이 사용자보다 넓은 권한의 도구를 호출 |
| 정보 유출 | 시스템 프롬프트·문맥의 다른 사용자 데이터 노출 |
| 공급망 | 외부 모델·데이터셋·MCP 서버·플러그인 |

기존 대응(입력 검증, 최소 권한, 출력 인코딩)은 그대로 필요하며, 여기에 "모델 출력은 신뢰할 수 없는 입력"이라는 원칙이 추가됩니다.

## 먼저 기억할 것

- 모델에 들어가는 모든 외부 텍스트(사용자 입력, 문서, 웹 페이지, 도구 결과)는 지시를 포함할 수 있습니다.
- 프롬프트 주입은 완전히 막을 수 없습니다. 주입이 성공해도 피해가 제한되도록 권한과 검증을 설계합니다.
- 모델 출력은 사용자 입력과 같은 신뢰 수준으로 다룹니다. 실행·렌더링·저장 전에 검증합니다.
- 모델이 접근할 수 있는 도구·데이터의 권한은 요청한 사용자의 권한을 넘지 않아야 합니다.
- 시스템 프롬프트는 비밀이 아닙니다. 비밀은 프롬프트에 넣지 않습니다.
