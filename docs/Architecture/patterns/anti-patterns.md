# 아키텍처 안티패턴

안티패턴은 처음에는 합리적으로 보였지만 반복해서 같은 문제를 일으키는 구조입니다. 각 항목에 대해 **신호, 생기는 이유, 대응**을 정리합니다. 신호가 보일 때 이름을 붙일 수 있으면 논의가 빨라집니다.

## 한눈에 보기

| 안티패턴 | 한 줄 신호 |
| --- | --- |
| 큰 진흙 덩어리 | 경계 없음, 모든 것이 모든 것을 호출 |
| 분산 모놀리스 | 서비스는 여럿인데 항상 함께 배포 |
| 공유 DB | 여러 모듈·서비스가 같은 테이블 쓰기 |
| 빈 계층 | 단순 위임만 하는 계층 |
| 신 객체·신 서비스 | 모든 로직이 한 클래스·서비스에 |
| 순환 의존 | A→B→A |
| 골든 해머 | 모든 문제에 같은 기술 |
| 이력서 주도 설계 | 필요와 무관한 신기술 도입 |
| 추측성 일반화 | 쓰지 않는 확장점·추상화 |
| 분산 트랜잭션 의존 | 서비스 간 2PC·동기 롤백 |

## 항목별

### 큰 진흙 덩어리(Big Ball of Mud)

| 항목 | 내용 |
| --- | --- |
| 신호 | 기능 하나에 수십 파일 수정, 어디서 무엇이 바뀌는지 추적 불가 |
| 이유 | 경계 없이 빠르게 추가, 규칙 미강제 |
| 대응 | 가장 자주 바뀌는 영역부터 모듈 추출, 의존 규칙 도구로 강제, [스트랭글러](../process/migration-and-debt.md) |

### 분산 모놀리스

| 항목 | 내용 |
| --- | --- |
| 신호 | 서비스 하나 배포에 다른 서비스도 배포, 동기 호출 체인, 공유 라이브러리의 업무 모델 |
| 이유 | 모듈 경계 없이 기술 단위로 서비스 분리 |
| 대응 | 서비스 병합(모듈러 모놀리스로 회귀)이 현실적. 경계 재정의 후 재분리 |

### 공유 데이터베이스

| 항목 | 내용 |
| --- | --- |
| 신호 | 스키마 변경 시 여러 팀 조율, 어느 코드가 테이블을 쓰는지 불명 |
| 이유 | 조인이 편해서, 데이터 소유권 미정의 |
| 대응 | 소유자 지정, 타 모듈 접근을 API·뷰·복제본으로 전환([경계 설계](./boundaries.md)) |

### 빈 계층(Lasagna)

| 항목 | 내용 |
| --- | --- |
| 신호 | 컨트롤러→서비스→리포지토리가 모두 한 줄 위임, 도메인 계층에 로직 없음 |
| 이유 | 규칙이 단순한데 교과서적 계층을 강제 |
| 대응 | 계층 제거 또는 통합. 규칙이 생기면 그때 분리 |

### 신 객체·신 서비스

| 항목 | 내용 |
| --- | --- |
| 신호 | 수천 줄 클래스, `Manager`·`Util`·`Common` 이름, 모든 PR이 같은 파일 수정 |
| 이유 | 어디 둘지 모를 때 기존 큰 곳에 추가 |
| 대응 | 변경 이유별로 분리, 새 코드는 새 모듈에, 큰 파일 수정 금지 규칙 |

### 순환 의존

| 항목 | 내용 |
| --- | --- |
| 신호 | 두 모듈을 따로 빌드·테스트 불가, import 순서 문제 |
| 이유 | 편의상 서로 참조 |
| 대응 | 공통 부분을 제3 모듈로 추출, 한쪽을 인터페이스·이벤트로 역전 |

### 골든 해머와 이력서 주도 설계

| 항목 | 내용 |
| --- | --- |
| 신호 | 요구와 무관한 기술 선택, "다들 쓰니까", 팀이 운영 못 하는 기술 |
| 이유 | 익숙함 또는 호기심이 요구 분석을 대체 |
| 대응 | 품질 속성 시나리오로 요구 명시, ADR에 대안 비교 기록([ADR](../process/adr.md)) |

### 추측성 일반화

| 항목 | 내용 |
| --- | --- |
| 신호 | 구현이 하나뿐인 인터페이스, 쓰이지 않는 설정·플러그인 구조, "나중을 위해" |
| 이유 | 미래 요구를 예측하려 함 |
| 대응 | 현재 요구에 맞는 가장 단순한 구조, 실제 두 번째 사례가 생길 때 추출 |

### 분산 트랜잭션 의존

| 항목 | 내용 |
| --- | --- |
| 신호 | 서비스 간 2단계 커밋, 동기 호출 실패 시 수동 롤백 코드 |
| 이유 | 결과적 일관성을 피하려 함 |
| 대응 | 경계 재검토(한 트랜잭션이어야 하면 한 모듈), 사가·아웃박스([이벤트 기반](../styles/event-driven.md)) |

## 구조 문제를 드러내는 지표

| 지표 | 측정 | 경고 신호 |
| --- | --- | --- |
| 변경 결합 | 함께 수정되는 파일 쌍(git 이력) | 다른 모듈의 파일이 자주 함께 변경 |
| 모듈 간 의존 수 | 의존성 그래프 | 특정 모듈로 집중, 순환 |
| 파일 크기·변경 빈도 | 상위 파일 | 큰 파일이 자주 변경 |
| 배포 결합 | 동시 배포 빈도 | 서비스가 항상 함께 배포 |
| 리드 타임 | 변경→배포 | 특정 영역만 느림 |

지표는 [피트니스 함수](../quality/fitness-functions.md)로 지속 측정합니다.
