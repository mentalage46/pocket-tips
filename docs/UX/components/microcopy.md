# UX 라이팅

인터페이스의 문구(라벨, 버튼, 안내, 오류, 빈 상태)는 사용자가 다음에 무엇을 할지 결정하는 근거입니다. 짧고 구체적이며 일관된 문구는 디자인 변경 없이도 사용성을 크게 올립니다. 한국어 인터페이스 기준으로 정리합니다.

## 기본 원칙

| 원칙 | 나쁜 예 | 좋은 예 |
| --- | --- | --- |
| 명확 > 재치 | "앗, 뭔가 잘못됐어요!" | "저장하지 못했습니다. 다시 시도해 주세요." |
| 짧게 | "입력하신 비밀번호가 올바르지 않습니다. 다시 확인하신 후 입력해 주시기 바랍니다." | "비밀번호가 올바르지 않습니다." |
| 구체적 | "오류가 발생했습니다" | "파일 크기가 10MB를 넘습니다" |
| 사용자 관점 | "요청이 처리되었습니다" | "주문이 완료되었습니다" |
| 능동·동작 중심 | "삭제가 수행됩니다" | "삭제합니다" |
| 일관된 용어 | 삭제/제거/지우기 혼용 | 하나로 통일 |
| 전문 용어 회피 | "세션이 만료되었습니다" | "오래 사용하지 않아 로그아웃되었습니다" |

## 톤

| 요소 | 권장 |
| --- | --- |
| 높임 | 존댓말("~합니다", "~해 주세요"). "~하세요"는 지시적, "~해 주세요"는 요청 |
| 주어 | 시스템을 "저희"·"우리"로 부르지 않음. 필요하면 서비스 이름 |
| 사용자 호칭 | "고객님"·"회원님"은 꼭 필요할 때만. 대부분 생략 가능 |
| 감탄·이모지 | 제한적. 오류·결제·보안에서는 금지 |
| 사과 | 시스템 잘못일 때 한 번. 과도한 사과는 신뢰 저하 |
| 긴급도 | 실제 위험만 강한 표현. 모든 것이 "경고"면 무시됨 |

## 버튼과 동작

| 규칙 | 나쁜 예 | 좋은 예 |
| --- | --- | --- |
| 동사로 결과를 말함 | "확인" | "저장", "삭제", "결제하기" |
| 예/아니오 금지 | "예 / 아니오" | "삭제 / 취소" |
| 대상 포함(모호할 때) | "제출" | "신청서 제출" |
| 길이 | 2~4어절 | |
| 진행 중 | 같은 동사 + "중" | "저장 중…" |
| 링크 문구 | "여기를 클릭" | "요금제 비교 보기" |

## 라벨과 안내

| 요소 | 규칙 | 예 |
| --- | --- | --- |
| 필드 라벨 | 명사, 짧게, 단위 포함 | "금액 (원)", "연락처" |
| 플레이스홀더 | 예시 값만, 라벨 대체 금지 | "예: 010-1234-5678" |
| 도움말 | 형식·제약·이유 | "8자 이상, 숫자 포함" |
| 섹션 제목 | 내용을 요약하는 명사구 | "배송 정보" |
| 빈 상태 | 상황 + 다음 행동 | "아직 프로젝트가 없습니다. 첫 프로젝트를 만들어 보세요." |
| 툴팁 | 한 문장 | "다운로드 링크는 24시간 뒤 만료됩니다" |

## 오류와 경고

| 구성 | 내용 |
| --- | --- |
| 무엇이 | "이메일 주소 형식이 아닙니다" |
| 왜(필요하면) | "같은 이름의 파일이 이미 있습니다" |
| 어떻게 | "다른 이름을 입력하거나 기존 파일을 덮어쓰세요" |

| 피할 것 | 대신 |
| --- | --- |
| "잘못된", "유효하지 않은", "실패" 반복 | 구체적 상태 |
| 오류 코드만 | 사람의 말 + 코드는 보조 |
| 부정문 중첩 | "~하지 않으면 ~할 수 없습니다" → "~하면 ~할 수 있습니다" |
| 책임 전가 | "입력을 잘못하셨습니다" → "확인해 주세요" |

## 확인과 알림

| 상황 | 문구 구조 | 예 |
| --- | --- | --- |
| 확인 대화상자 제목 | 대상 + 동작 + ? | "'설계 문서'를 삭제하시겠습니까?" |
| 확인 본문 | 결과·되돌림 가능 여부 | "삭제한 문서는 30일 안에 휴지통에서 복구할 수 있습니다." |
| 성공 토스트 | 대상 + 완료 | "설정을 저장했습니다" |
| 실행 취소 | 결과 + 되돌리기 | "메시지를 삭제했습니다 [실행 취소]" |
| 진행 알림 | 상태 + 예상 | "내보내는 중… 약 1분 소요" |

## 숫자·날짜·단위

| 항목 | 규칙 |
| --- | --- |
| 숫자 | 천 단위 쉼표, 단위 띄어쓰기("1,200 원"보다 "1,200원"은 관례 허용. 제품 내 통일) |
| 날짜 | 명확한 형식(2026-03-10 또는 2026년 3월 10일). 상대 시간("3분 전")은 최근만, 툴팁에 절대 시간 |
| 시간대 | 사용자 시간대, 필요 시 표기 |
| 남은 수 | "3개 남음", 0일 때 문구 따로 |
| 복수 | 한국어는 "들" 불필요. 영어 번역 시 단·복수 분기 |

## 용어집 운영

| 항목 | 내용 |
| --- | --- |
| 용어집 | 개념별 공식 용어, 금지 용어, 영문 대응 |
| 문구 자산 | 반복 문구(오류, 확인)를 코드 상수·번역 키로 관리 |
| 리뷰 | 새 문구는 용어집과 대조, 디자인 리뷰에 포함 |
| 번역 | 원문이 짧고 명확해야 번역도 좋음([다국어 관리](../../I18N/README.md)) |

## 점검표

| 질문 |
| --- |
| 버튼만 읽어도 무슨 일이 일어날지 아는가 |
| 오류 메시지에 해결 방법이 있는가 |
| 같은 개념을 같은 단어로 부르는가 |
| 기술 용어·내부 용어가 노출되는가 |
| 문장을 절반으로 줄일 수 있는가 |
