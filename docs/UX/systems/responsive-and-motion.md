# 반응형과 모션

같은 기능이 폰, 태블릿, 데스크톱에서 각각 자연스럽게 동작해야 하고, 상태 변화는 사용자가 따라올 수 있는 속도로 일어나야 합니다. 반응형은 **레이아웃이 어떻게 적응하는가**, 모션은 **변화를 어떻게 설명하는가**의 문제입니다.

## 브레이크포인트

| 이름 | 폭(예) | 대표 기기 | 레이아웃 |
| --- | --- | --- | --- |
| sm | ~640px | 폰 | 1열, 하단 탭, 드로어 메뉴 |
| md | 641~1024px | 태블릿, 작은 노트북 | 2열, 접힌 사이드바 |
| lg | 1025~1440px | 데스크톱 | 사이드바 + 본문, 다열 |
| xl | 1441px~ | 와이드 | 최대 폭 제한, 여백 확대 |

| 원칙 | 설명 |
| --- | --- |
| 콘텐츠 기준 | 기기 목록이 아니라 레이아웃이 깨지는 지점에서 브레이크포인트 |
| 모바일 우선 | 작은 화면 기본 → 넓어지면 확장. CSS도 `min-width` 미디어 쿼리 |
| 수 제한 | 3~4개. 많으면 관리 불가 |
| 컨테이너 쿼리 | 컴포넌트는 뷰포트가 아니라 담긴 영역 폭에 반응(`@container`) |
| 유동 값 | `clamp()`로 글꼴·간격을 연속적으로 |

## 레이아웃 적응 패턴

```mermaid
flowchart LR
    D[데스크톱: 사이드바 + 본문 + 상세 패널] --> T[태블릿: 접힌 사이드바 + 본문, 상세는 드로어]
    T --> M[모바일: 하단 탭, 본문, 상세는 전체 화면]
```

| 요소 | 넓은 화면 | 좁은 화면 |
| --- | --- | --- |
| 내비게이션 | 사이드바, 상단 메뉴 | 하단 탭(주요 3~5), 드로어(나머지) |
| 표 | 전체 열 | 핵심 열 + 상세 펼침, 또는 카드 |
| 폼 | 2열 가능 | 1열 |
| 모달 | 중앙 대화상자 | 전체 화면 또는 바텀 시트 |
| 상세 | 옆 패널 | 새 화면(뒤로 가기) |
| 툴바 | 모든 버튼 | 주요 1~2개 + 더보기 메뉴 |
| 이미지 | 고정 크기 | `srcset`, 비율 유지 |

## 터치와 포인터

| 항목 | 터치 | 마우스 |
| --- | --- | --- |
| 목표 크기 | 44×44px 이상, 간격 8px | 24px 이상 |
| 호버 | 없음. 호버에만 의존한 기능 금지 | 가능 |
| 제스처 | 스와이프·길게 누르기는 보조. 보이는 대안 필수 | - |
| 엄지 영역 | 주요 동작은 화면 하단·중앙 | - |
| 입력 | 가상 키보드가 화면 절반 차지. 포커스 시 스크롤 | - |
| 감지 | `@media (hover: hover)`, `(pointer: coarse)`로 분기 | |

## 플랫폼 관례

| 항목 | 웹 | iOS | Android |
| --- | --- | --- | --- |
| 뒤로 가기 | 브라우저 버튼, 브레드크럼 | 좌상단 ‹, 스와이프 | 시스템 뒤로 가기 |
| 주 내비게이션 | 상단·사이드 | 하단 탭 바 | 하단 내비게이션·드로어 |
| 확인 대화상자 | 중앙 | 액션 시트 | 다이얼로그·바텀 시트 |
| 플랫폼 가이드 | - | Human Interface Guidelines | Material Design |

웹앱이라도 모바일에서는 해당 OS 관례를 존중합니다.

## 모션의 목적

| 목적 | 예 |
| --- | --- |
| 변화 설명 | 항목이 어디서 와서 어디로 갔는지(목록 재정렬, 패널 열림) |
| 피드백 | 버튼 눌림, 토글 전환 |
| 주의 유도 | 새 알림 배지, 오류 필드 흔들림(절제) |
| 연속성 | 화면 전환 시 공유 요소 이동 |
| 대기 표현 | 로딩 스켈레톤, 진행률 |

장식 목적의 모션은 두 번째 볼 때부터 방해가 됩니다. "이 모션이 없으면 사용자가 무엇을 놓치는가"에 답이 없으면 뺍니다.

## 지속 시간과 이징

| 변화 | 지속 시간 | 이징 |
| --- | --- | --- |
| 작은 상태(호버, 체크) | 100~150ms | ease-out |
| 요소 등장·사라짐 | 150~250ms | 등장 ease-out, 사라짐 ease-in |
| 패널·드로어 | 200~300ms | ease-in-out |
| 화면 전환 | 250~400ms | 표준 곡선 |
| 큰 이동·복잡한 전환 | 최대 500ms | |

| 원칙 | 설명 |
| --- | --- |
| 사라짐은 빠르게 | 등장보다 짧게 |
| 거리 비례 | 멀리 움직일수록 약간 길게, 선형 비례는 아님 |
| 토큰화 | `duration-fast/base/slow`, `easing-standard`로 통일 |
| 성능 | `transform`·`opacity`만 애니메이션. 레이아웃 속성(width, top) 금지 |

## 모션 접근성

| 항목 | 내용 |
| --- | --- |
| 동작 줄이기 설정 | `prefers-reduced-motion: reduce`에서 이동·확대 애니메이션 제거, 페이드로 대체 |
| 자동 재생 | 5초 이상 움직이는 콘텐츠는 정지 수단 |
| 깜빡임 | 초당 3회 이상 금지(광과민성) |
| 시차·패럴랙스 | 멀미 유발. 줄이기 설정에서 제거 |

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```

## 점검표

| 질문 |
| --- |
| 320px 폭에서 가로 스크롤 없이 모든 기능이 되는가 |
| 터치 목표가 44px 이상인가 |
| 호버 없이 모든 기능에 접근 가능한가 |
| 가상 키보드가 열렸을 때 입력 필드가 보이는가 |
| 동작 줄이기 설정에서 콘텐츠가 멈추는가 |
| 애니메이션이 transform·opacity만 쓰는가 |
