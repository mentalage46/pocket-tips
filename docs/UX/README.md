# UX/UI

UX(사용자 경험)는 사용자가 목표를 얼마나 쉽게, 확실하게, 기분 좋게 달성하는가이고, UI(사용자 인터페이스)는 그 경험이 드러나는 화면과 상호작용입니다. 이 폴더는 개발자가 디자이너와 협업하거나 직접 화면을 설계할 때 필요한 원칙, 시각 요소, 컴포넌트 규칙, 디자인 시스템, 협업 절차를 다룹니다.

## 개발자에게 UX가 필요한 순간

| 상황 | 참고 |
| --- | --- |
| 디자이너 없이 관리 화면·내부 도구를 만듦 | 원칙, 컴포넌트 규칙, 폼, 피드백 |
| 디자인 시안을 구현하며 빠진 상태를 채워야 함 | 피드백과 상태, 반응형 |
| 디자인 시스템을 코드로 옮김 | 디자인 시스템, 색상, 타이포그래피 |
| 사용자 불만이 있는데 원인을 모름 | 사용자 조사, 협업과 측정 |
| 오류 메시지·라벨을 직접 씀 | UX 라이팅 |

## 먼저 기억할 것

- 사용자는 화면을 읽지 않고 훑습니다. 가장 중요한 것이 가장 먼저 보여야 합니다.
- 모든 상호작용에는 즉각적인 피드백이 필요합니다. 아무 일도 안 일어난 것처럼 보이는 것이 최악입니다.
- 일관성이 참신함보다 중요합니다. 같은 것은 같게, 다른 것은 다르게 보여야 합니다.
- 접근성은 별도 작업이 아니라 기본 품질입니다. 대비, 키보드, 포커스, 레이블을 처음부터 넣습니다.
- 추측 대신 관찰합니다. 사용자 다섯 명만 지켜봐도 대부분의 문제가 드러납니다.
