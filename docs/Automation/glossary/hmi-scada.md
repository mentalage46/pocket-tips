# HMI·SCADA 용어

[전체 용어 색인](./README.md)

## HMI 설계

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| HMI / Human-Machine Interface | 운전자가 설비 한 대·한 라인의 상태를 보고 조작하는 화면입니다. 좋은 HMI는 정상일 때는 조용하고, 이상이 생기면 바로 눈에 띄며, 실수로 잘못 누르기 어렵습니다. |
| SCADA / Supervisory Control and Data Acquisition | 여러 PLC·현장을 모아 감시·제어하고 알람·이력을 저장하는 시스템입니다. 흔히 ISA-95 Level 2로 설명하지만 Level 3 예시에 넣는 자료도 있어, 시스템별 책임을 문서로 정하는 것이 더 중요합니다. |
| MES / Manufacturing Execution System | 생산 지시·실적·품질·LOT 추적을 관리하는 공장 운영 시스템으로 ISA-95 Level 3에 해당합니다. |
| ISA-101·IEC 63303 | 공정 자동화용 HMI 표준과 이를 바탕으로 한 국제 표준입니다. 철학 문서·스타일 가이드·생애주기처럼 무엇을 해야 하는지를 정할 뿐, "배경은 회색" 같은 구체 값을 정하지는 않습니다. |
| 고성능 HMI / High Performance HMI | 원시 데이터가 아니라 정보를 보여 주는 HMI 설계 관행입니다. 차분한 회색 계열 배경에 알람·비정상 상태에만 눈에 띄는 색을 쓰지만, 색을 모두 빼라는 뜻은 아닙니다. |
| HMI 철학·스타일 가이드·툴킷 / Philosophy, Style guide, Toolkit | HMI 생애주기의 문서 3종입니다. 철학은 사업장 공통 원칙과 이유, 스타일 가이드는 특정 플랫폼에 적용한 색·글꼴·배치 규칙, 툴킷은 심볼·페이스플레이트·템플릿 같은 재사용 객체 라이브러리입니다. |
| 화면 계층 / Display hierarchy, Level 1–4 | 개요, 공정 단위, 단위 상세, 지원·진단으로 나눈 4단계 화면 구분입니다. ISA-95 레벨과는 다른 분류이고 이름도 자료마다 조금씩 다르며, 모든 설비가 4단계를 다 필요로 하지는 않습니다. |
| 페이스플레이트 / Faceplate | 설비 하나의 상세 상태와 조작을 담아 띄우는 팝업 화면으로 툴킷에 포함되는 재사용 객체입니다. 겹친 팝업이 공정을 가리지 않도록 한두 개까지만 띄웁니다. |
| 아날로그 표시기 / Analog indicator | 정상·경고 범위를 띠로 표시한 막대·게이지입니다. 숫자만 나열하면 정상 범위 판단을 운전자 머릿속에 맡기게 됩니다. |
| 스파크라인 / Sparkline | 핵심 변수 옆에 넣는 짧은 추세 그래프입니다. 천천히 변하는 공정 변수의 방향과 속도를 보여 줍니다. |
| 알람 배너 / Alarm banner | 모든 화면의 상단 또는 하단에 고정해 최신·최고 우선순위 알람을 보여 주는 영역입니다. 알람을 누르면 해당 설비 화면으로 바로 이동하게 만듭니다. |
| 2단계 조작 / Two-step operation | 대상을 고른 뒤 동작 버튼을 누르게 하는 기동·정지·모드 전환용 조작 방식입니다. 확인 대화상자는 "P-101 펌프 정지"처럼 바꿀 내용을 구체적으로 쓰고, 자주 쓰는 일상 조작에는 쓰지 않습니다. |
| 모멘터리 조작 / Momentary operation | 조그나 수동 밸브 개도처럼 누르는 동안만 동작하고 손을 떼면 멈추는 조작입니다. |
| P&ID / Piping and Instrumentation Diagram | 배관·계기 도면입니다. 화면에 그대로 옮기면 정보가 흩어지고 숫자만 가득해지므로 운전 과업에 맞춰 필요한 정보를 묶어 배치합니다. |
| 색 외 수단 / Non-color cues | 모양·텍스트·채움으로 상태를 구분하는 방법입니다. 남성 약 12명 중 1명이 색각 이상이므로 알람 우선순위는 색과 아이콘 모양 두 가지로 구분합니다. |

관련 문서: [HMI 화면 설계](../hmi-scada/hmi-design.md)

## 알람 관리

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| 알람 / Alarm | 설비 고장·공정 이탈·비정상 상태를 알리며 운전자의 시기적절한 대응이 필요한 것입니다. 운전자 조치가 없거나 급하지 않은 "모터 기동됨", "배치 완료" 같은 상태 변화는 알람이 아니라 이벤트입니다. |
| ISA-18.2·IEC 62682 | 공정 산업 알람 관리 표준과 같은 계열의 국제 표준입니다. 알람 관리를 철학부터 감사까지 A–J의 10단계 생애주기로 보며, EEMUA 191은 같은 분야의 지침입니다. |
| 알람 철학 / Alarm philosophy | 알람 정의, 우선순위 기준, 색·소리, 셸빙 규칙, 성능 목표, 역할과 책임을 정한 문서입니다. 알람 생애주기의 첫 단계입니다. |
| 합리화 / Rationalization | 알람 후보마다 원인·결과·운전자 조치·허용 대응 시간·우선순위·한계값을 검토해 확정하는 작업으로, 결과는 마스터 알람 데이터베이스에 남깁니다. 원인·결과·조치를 적지 못하는 알람은 삭제 후보입니다. |
| 알람 우선순위 / Alarm priority | 결과의 심각도와 운전자가 대응할 수 있는 시간으로 정하는 알람 등급입니다. "높음"이 많으면 의미를 잃으므로 낮음 약 80%, 중간 약 15%, 높음 약 5% 같은 분포를 목표로 봅니다. |
| 알람 홍수 / Alarm flood | 운전자가 처리할 수 있는 수준을 넘는 알람 폭주입니다. 공개 자료의 성능 지표는 10분에 10개 초과를 홍수로 측정합니다. |
| 채터링·순간 알람 / Chattering, Fleeting alarm | 짧은 시간에 발생과 해제를 반복하는 알람과, 운전자가 조치할 틈도 없이 매우 짧게 울렸다 사라지는 알람입니다. 데드밴드와 지연으로 줄입니다. |
| 장기 활성·상시 알람 / Stale, Standing alarm | 24시간 넘게 계속 활성인 알람과, 특정 시점에 활성 상태로 남아 있는 알람입니다. 상시 알람 개수 목표는 철학 문서에서 정합니다. |
| 상위 잦은 알람 / Bad actor | 전체 알람의 큰 몫을 차지하는 소수 태그의 알람입니다. 목록을 주기적으로 보고 위에서부터 고치는 것이 가장 효과가 큽니다. |
| 확인·미확인 / Acknowledged, Unacknowledged | 운전자가 알람을 보았다고 표시했는지를 나타내는 상태입니다. 깜박임은 미확인일 때만 쓰고, 조건은 사라졌지만 확인하지 않은 정상 복귀 미확인(RTN Unacknowledged) 상태도 따로 있습니다. |
| 래치 알람 / Latched alarm | 조건이 정상으로 돌아와도 리셋 전까지 유지되는 알람입니다. |
| 셸빙 / Shelving | 운전자가 통제된 방법으로 알람을 일시적으로 숨기는 것입니다. 시간 제한(자동 해제)과 셸빙 목록 화면이 없으면 숨긴 알람이 영구히 잊힙니다. |
| 설계상 억제·서비스 제외 / Suppressed by Design, Out of Service | 운전 모드·설비 상태 로직이 알람을 억제하는 것과, 정비가 계기를 서비스에서 빼는 것입니다. 셸빙과 통제 주체가 다르며, OPC UA에서는 이 상태의 알람도 비활성화(Disabled)와 달리 계속 평가됩니다. |
| 알람 데드밴드 / Alarm deadband, Hysteresis | 알람 발생값과 해제값 사이에 두는 간격으로, 한계값 근처 잡음으로 인한 채터링을 막습니다. 히스토리안의 압축 데드밴드와는 다른 설정입니다. |
| 발생·해제 지연 / On-delay, Off-delay | 조건이 정해진 시간 동안 지속될 때만 알람을 발생시키거나 해제하는 기법입니다. 짧은 튐으로 인한 순간 알람과 빠른 반복 해제·재발생을 막습니다. |
| 1차 원인 / First-out | 트립 시 연쇄 알람 중 최초 원인 하나를 래치해 보여 주는 기법입니다. 같은 스캔에 여러 조건이 들어오면 코드 순서가 우선순위가 되므로, 정확한 순서가 필요하면 입력 모듈의 타임스탬프 기능(SOE, Sequence of Events)을 씁니다. |
| 변경 관리 / Management of Change, MOC | 알람 추가·삭제·한계 변경 같은 변경을 승인 절차로 처리하는 것입니다. 운전자가 알람 한계를 임의로 바꾸면 근거 없는 한계가 남습니다. |

관련 문서: [알람 관리](../hmi-scada/alarm-management.md), [시퀀스 패턴](../programming/sequence-patterns.md)

## 태그와 데이터

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| 태그 / Tag | PLC 주소·OPC UA 노드 같은 데이터 원천에 이름·단위·스케일·알람·이력 설정을 붙인 것입니다. PLC 주소를 태그 이름으로 쓰면 주소가 바뀔 때 모든 화면을 고쳐야 합니다. |
| ISA-5.1 계기 태그 / Instrument tag | `FIC-101`처럼 첫 글자가 측정 변수, 뒤 글자가 기능을 뜻하는 계기 번호입니다. P&ID·계기 리스트와 1:1로 맞지만 위치·설비 문맥이 이름에 없고 공장 간에 중복될 수 있습니다. |
| 계층형 태그 이름 / Hierarchical naming | `Acme/Seoul/Packing/Line1/Filler/Speed`처럼 ISA-95 계층을 경로로 쓰는 이름입니다. 여러 공장 통합과 검색에 유리하고, 경로 끝에 계기 태그를 남기면 계기 리스트와 추적할 수 있습니다. |
| UDT / User-Defined Type | 같은 종류 설비의 태그 구조를 한 번 정의하고 인스턴스로 만드는 사용자 정의 타입입니다. UDT에 태그를 추가하면 모든 인스턴스에 반영되고, 화면 심볼은 인스턴스 경로만 받아 재사용합니다. |
| 스케일링·공학 단위 / Scaling, Engineering Unit, EU | 아날로그 원시값을 % 같은 공학 단위로 선형 변환하는 것입니다. PLC나 SCADA 중 한 곳에서만 해야 이중 스케일링 버그를 막을 수 있습니다. |
| 품질 코드 / Quality, OPC UA StatusCode | 값을 믿어도 되는지 나타내는 Good·Uncertain·Bad 표시입니다. 통신이 끊긴 마지막 값을 정상으로 착각하지 않도록 값·품질·시각을 항상 함께 다루고, Bad 품질 값으로 알람을 판정하지 않습니다. |
| 원천 시각 / Source timestamp | 값이 생긴 곳에서 찍은 시각입니다. 서버가 값을 받은 시각과 구분하고 원천 시각을 우선합니다. |
| 히스토리안 / Historian | 공정 데이터를 시계열로 저장·조회하는 시스템입니다. 의미 있는 변화만 저장하도록 예외 검사와 압축을 거치며, 품질 변화도 함께 기록합니다. |
| 예외 검사 / Exception | 직전 보고값 대비 데드밴드 안의 변화를 버리는 히스토리안 앞단의 필터입니다. AVEVA PI 기준으로 수집 인터페이스가 수행하며 지원 여부는 인터페이스마다 다릅니다. |
| 스윙잉 도어 압축 / Swinging door compression | 저장된 점 사이를 직선 보간해 허용 오차 안에서 복원할 수 있으면 중간 점을 버리는 압축 알고리즘입니다. 압축 데드밴드가 너무 크면 짧은 변동·피크를 잃어 분석과 사고 조사가 어려워집니다. |
| 저장 후 전송 / Store and forward | 상위 연결이 끊기면 로컬 버퍼에 쌓았다가 복구 후 보내는 기능입니다. 엣지·원격 사이트에 필요하며, Sparkplug에서는 명세상 선택 사항입니다. |
| 주·대기 이중화 / Hot standby | 대기 서버가 상태를 동기화하며 기다리다 주 서버 장애 시 이어받는 구성입니다. 두 서버가 동시에 PLC에 쓰지 않게 하고, 이중화 노드에도 라이선스가 필요한 경우가 많습니다. |
| 웹 HMI / Web-based HMI, HTML5 client | 설치 없이 브라우저로 접속하는 HMI 클라이언트입니다. 인터넷에 직접 노출하지 않고 VPN·DMZ·원격 접속 게이트웨이를 거치게 합니다. |
| 엣지 게이트웨이 / Edge gateway | 현장에서 데이터를 수집·버퍼링·전처리해 상위로 보내는 장치입니다. PLC와는 OPC UA로, 상위와는 MQTT로 연결하는 조합이 흔하며 클라우드 연결이 끊겨도 현장 운전은 계속되어야 합니다. |

관련 문서: [태그와 SCADA 구성](../hmi-scada/tags-and-architecture.md), [OPC UA와 MQTT](../communication/opc-ua-and-mqtt.md)
