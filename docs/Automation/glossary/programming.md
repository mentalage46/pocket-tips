# 프로그래밍 용어

[전체 용어 색인](./README.md)

## 표준과 언어

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| IEC 61131-3 | PLC 프로그래밍 언어와 프로그램 구조를 정한 국제 표준으로 현재 4판(2025)입니다. 표준이 바뀌어도 제조사 도구가 바로 따라가지 않으므로 실제로 쓸 수 있는 기능은 도구 매뉴얼로 확인합니다. |
| 래더 다이어그램 / Ladder Diagram, LD | 접점과 코일을 렁으로 배치하는 그래픽 언어로, 현장 보전 인력이 가장 많이 봅니다. 전기 회로처럼 보이지만 위에서 아래로 실행되는 프로그램이라 렁 순서를 바꾸면 결과가 달라질 수 있습니다. |
| 기능 블록 다이어그램 / Function Block Diagram, FBD | 블록을 선으로 연결해 신호 흐름을 그리는 그래픽 언어입니다. 아날로그·PID 흐름은 잘 보이지만 분기·순서 제어가 많아지면 선이 얽힙니다. |
| 구조화 텍스트 / Structured Text, ST | `IF`, `CASE`, `FOR`를 쓰는 Pascal 계열 텍스트 언어로, Siemens에서는 SCL이라고 부릅니다. 계산·배열·상태 머신과 텍스트 diff에 강하지만 현장 보전 인력에게는 낯설 수 있습니다. |
| 순차 기능 차트 / Sequential Function Chart, SFC | 스텝·전이·액션으로 공정 순서를 그리는 구조 언어입니다. 각 스텝의 액션과 전이 조건은 LD·ST 같은 다른 언어로 쓰며, 도구 간 구현 차이가 크고 텍스트 diff가 어렵습니다. |
| 명령어 리스트 / Instruction List, IL | 어셈블리와 비슷한 누산기 명령 언어입니다. 3판에서 폐기 예정으로 지정되고 4판에서 삭제되었다고 알려져 있어 새 코드에는 쓰지 않지만, 하위 호환으로 계속 지원하는 도구도 있습니다. |
| IEC 61499 | 이벤트 입력으로 실행되는 기능 블록을 여러 장치에 분산 배치하는 별도 표준입니다. IEC 61131-3이 한 PLC 안의 주기 실행을 다룬다면 IEC 61499는 장치에 나뉜 애플리케이션과 이벤트 흐름을 다루며, 아직 IEC 61131-3만큼 널리 쓰이지 않습니다. |
| PLCopen XML / IEC 61131-10 | IEC 61131-3 프로젝트를 도구 사이에서 교환하는 XML 형식으로, IEC 61131-10으로 표준화되었습니다. 도구마다 지원 범위가 달라 내보내기·가져오기를 왕복하면 정보가 빠질 수 있습니다. |

관련 문서: [IEC 61131-3 개요](../programming/iec-61131-3.md), [최신 실무: 버전 관리·테스트·AI](../programming/modern-practices.md)

## 프로그램 구조와 데이터

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| POU / Program Organization Unit | 프로그램을 이루는 기본 단위로 `FUNCTION`, `FUNCTION_BLOCK`, `PROGRAM`이 있습니다. FUNCTION은 내부 상태가 없어 같은 입력이면 같은 출력을 내고, PROGRAM은 태스크에 연결되어 실행되는 최상위 로직입니다. |
| 기능 블록·인스턴스 / FUNCTION_BLOCK, Instance | 호출 사이에 값을 유지하는 POU와, 그 POU를 선언할 때마다 따로 생기는 메모리입니다. 같은 인스턴스를 여러 곳에서 호출하거나 조건부로 건너뛰면 타이머·엣지 상태가 꼬입니다. |
| 구성·리소스·태스크 / Configuration, Resource, Task | 표준 소프트웨어 모델의 계층입니다. 구성은 PLC 시스템 전체, 리소스는 보통 CPU 하나, 태스크는 주기 또는 이벤트로 시작하고 우선순위를 가진 실행 조건입니다. |
| 데이터 타입 / Data type | `BOOL`, `INT`, `DINT`, `REAL`, `TIME`처럼 값의 크기와 해석을 정하는 것입니다. `INT`는 32767 다음에 음수로 넘어가므로 누적값에는 `DINT`를 쓰고, `REAL` 값은 `=`로 비교하지 않습니다. |
| 사용자 정의 타입 / STRUCT, ARRAY, ENUM | 여러 값을 묶은 구조체, 배열, 열거형입니다. PLC 구조체를 SCADA의 UDT·화면 심볼과 맞추면 설비 하나를 추가할 때 세 곳이 함께 생깁니다. |
| 변수 섹션 / VAR_INPUT, VAR_OUTPUT, VAR_IN_OUT, VAR_TEMP | 변수의 역할을 나누는 선언 영역입니다. `VAR_IN_OUT`은 참조로 전달되어 원본을 읽고 쓰고, `VAR_TEMP`는 호출할 때마다 초기화됩니다. |
| 전역 변수 / VAR_GLOBAL | 어느 POU에서나 접근하는 변수입니다. 값이 어디서 바뀌는지 추적하기 어려우므로 I/O 매핑과 HMI 인터페이스 정도로 제한합니다. |
| 직접 주소 / Direct address, %IX·%QX·%MW | `%` + 위치(I 입력, Q 출력, M 메모리) + 크기 + 번호로 쓰는 표준 주소 표기입니다. 숫자 주소 형식은 제조사마다 달라 `%I0.0`, `X0`, `P00000`, `Local:1:I.Data.0`처럼 보입니다. |
| 심볼릭 주소·태그 / Symbolic address, Tag | 물리 주소 대신 `xStartPb` 같은 이름으로 변수에 접근하는 방식입니다. 배선이 바뀌어도 선언 한 곳만 고치면 되며, 최근 도구는 태그 기반이 기본이고 물리 주소는 I/O 구성 화면에서 연결합니다. |

관련 문서: [IEC 61131-3 개요](../programming/iec-61131-3.md), [태그와 SCADA 구성](../hmi-scada/tags-and-architecture.md)

## 래더와 기본 명령

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| 렁 / Rung | 래더의 가로 한 줄로, 접점(조건)과 코일(결과)로 이루어진 논리식입니다. 렁 안에서는 왼쪽에서 오른쪽, 렁끼리는 위에서 아래로 평가하며 위 렁의 결과를 같은 스캔의 아래 렁이 바로 봅니다. |
| 접점 / Contact | 비트를 읽는 조건으로 렁 왼쪽에 둡니다. 프로그램의 a접점은 비트가 TRUE일 때, b접점은 FALSE일 때 통전하며, 현장 배선의 a/b 접점과는 따로 생각합니다. |
| 코일 / Coil | 렁의 결과를 비트에 쓰는 출력으로 렁 오른쪽 끝에 둡니다. 일반 코일은 통전되지 않으면 FALSE를 쓰므로 매 스캔 값을 덮어쓴다는 점을 기억합니다. |
| 자기유지 / Self-holding circuit | 시작 버튼과 병렬로 출력 자신의 a접점을 두어 손을 떼도 출력을 유지하는 회로입니다. 정지·과부하 조건을 직렬로 두면 정지 우선이 되고, 비유지 변수라면 복전 시 자동 재기동하지 않습니다. |
| 셋·리셋 코일 / SET, RESET coil | 통전되면 비트를 TRUE로 만들어 유지하거나 FALSE로 만드는 코일입니다. 같은 스캔에서 둘 다 참이면 나중에 실행된 렁이 이기며, SET한 비트는 전원 재투입·모드 전환·비상정지 복구 때 누가 RESET하는지 정해 둡니다. |
| SR·RS | 셋 우선(`SR`)과 리셋 우선(`RS`)을 명시하는 표준 기능 블록입니다. 우선순위를 렁 순서에 맡기는 것보다 의도가 잘 드러납니다. |
| 상승·하강 엣지 / Rising, Falling edge, R_TRIG·F_TRIG | 신호가 FALSE→TRUE 또는 TRUE→FALSE로 바뀐 스캔에만 참이 되는 조건입니다. 엣지 인스턴스는 이전 값을 기억하므로 같은 인스턴스를 두 곳에서 호출하거나 호출을 건너뛰면 엣지를 놓칩니다. |
| 타이머 / TON, TOF, TP | 입력 `IN`, 설정 시간 `PT`, 출력 `Q`, 경과 시간 `ET`를 가진 표준 기능 블록으로, TON은 켜짐 지연, TOF는 꺼짐 지연, TP는 일정 폭 펄스입니다. 조건문 안이 아니라 매 스캔 호출하고 `IN`으로 제어해야 하며, 정밀도는 스캔 주기의 영향을 받습니다. |
| 카운터 / CTU, CTD, CTUD | 입력 상승 엣지마다 현재값 `CV`를 늘리거나 줄이고 설정값 `PV`와 비교하는 기능 블록입니다. 입출력 이름과 `PV`·`CV` 타입은 구현마다 다르고, 스캔보다 빠른 펄스는 고속 카운터로 셉니다. |
| EN·ENO | 박스 명령의 실행 허가 입력과 결과 출력입니다. `MOVE` 같은 박스는 `EN`이 참인 동안 매 스캔 실행되므로 레시피 로드처럼 한 번만 할 동작은 엣지로 실행합니다. |
| 듀얼 코일 / Dual coil | 같은 출력을 두 렁 이상의 일반 코일로 쓰는 것으로, 마지막에 쓴 렁의 결과만 출력에 반영됩니다. 모니터링 화면에서는 앞 렁 코일이 켜진 것처럼 보여 더 헷갈리므로 조건을 한 렁에 OR로 모읍니다. |
| 인터록 / Interlock | 조건이 깨지면 해당 동작을 즉시 금지·정지하는 로직입니다. 정역 운전처럼 동시 투입이 위험하면 PLC 출력 고장·강제 출력에 대비해 하드웨어 인터록을 함께 두고, 사람을 보호하는 안전 기능을 대신하지 않습니다. |
| 피드백 감시 / Feedback monitoring | 출력을 냈는데 접촉기 보조 접점 같은 피드백이 정해진 시간 안에 들어오지 않으면 고장으로 보는 로직입니다. 접점 융착이나 접촉기 미동작을 찾아냅니다. |

## 시퀀스와 상태

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| 스텝 시퀀스 / Step sequence | 현재 단계를 정수 하나로 관리하고, 단계마다 전이 조건과 타임아웃을 두는 패턴입니다. 스텝 번호를 10 단위로 띄우면 나중에 사이 스텝을 끼워 넣기 쉽습니다. |
| 상태 머신 / State machine | 한 번에 하나의 상태만 활성이고 조건에 따라 다음 상태로 옮기는 구조입니다. ST에서는 열거형과 `CASE` 문으로 쓰고, 출력은 `CASE` 밖에서 상태로 계산하면 듀얼 코일을 막고 고장 상태에서 출력이 자동으로 꺼집니다. |
| 전이 조건 / Transition condition | 다음 스텝으로 넘어가는 조건입니다. "밸브 열기 출력을 냈다"가 아니라 "열림 센서가 들어왔다"처럼 명령이 아닌 결과로 전이합니다. |
| 감시 타임아웃 / Step timeout | 스텝이 정해진 시간 안에 끝나지 않으면 고장 스텝으로 보내는 감시입니다. 센서가 고장 나도 영원히 멈추지 않고, 스텝과 연결한 알람 번호로 멈춘 위치를 알려 줍니다. |
| 허가 조건 / Permissive | 시작할 때 확인하는 조건으로, 항상 확인하는 인터록과 구분합니다. 이름 붙인 비트로 만들어 HMI에 "왜 시작할 수 없는지"를 보여 줍니다. |
| 수동·자동·원점 복귀 / Manual, Auto, Homing | 설비 운전 모드입니다. 모드 전환은 정지 상태나 사이클 끝에서만 허용하고, 원점 복귀는 충돌하지 않는 순서로 모든 축·실린더를 기준 위치에 보냅니다. |
| 사이클 정지 / Cycle stop | 현재 사이클을 끝낸 뒤 멈추는 정지입니다. 즉시 정지와 나누어 두면 운전자가 공작물을 버리지 않고 설비를 멈출 수 있습니다. |
| 액션 한정자 / Action qualifier | SFC 액션의 실행 방식을 정하는 기호로 `N`(활성 동안), `S`(셋), `R`(리셋), `P`(진입 시 1회), `L`(시간 제한), `D`(지연) 등이 있습니다. 지원하는 한정자와 스텝 플래그 이름은 도구마다 조금씩 다릅니다. |
| ISA-88 / IEC 61512 | 배치 공정의 모델과 용어 표준으로, 레시피(무엇을 만들지)와 설비 제어(어떻게 움직일지)를 분리합니다. 제어 모듈(밸브·모터 FB)과 장비 모듈·페이즈(투입, 가열 같은 재사용 단위)로 코드를 나누는 데 참고할 수 있습니다. |
| PackML | OMAC이 만들고 ISA가 기술 보고서 ISA-TR88.00.02로 채택한 기계 상태·모드·태그 표준으로 17개 상태를 정의합니다. 내부 원인 일시 정지(Hold)와 상·하류 설비 때문인 일시 정지(Suspend)를 구분하고, Aborted에서는 Clear 명령 후에만 빠져나옵니다. |
| PackTags | PackML의 명령(Command)·상태(Status)·관리(Admin) 태그 묶음입니다. 상위 시스템과 상태·카운트·알람을 주고받는 데 씁니다. |

## 개발 도구와 검증

| 용어 / 영문·약어 | 뜻과 읽을 때 주의할 점 |
| --- | --- |
| 온라인 편집 / Online edit | PLC가 동작하는 중에 프로그램을 직접 고치는 기능입니다. 수정 내용을 저장소에 반영하지 않으면 다음 다운로드에서 사라지므로 수정 후 업로드·비교해 커밋합니다. |
| 강제 / Force | 프로그램과 상관없이 입출력 값을 고정하는 기능입니다. 프로그램 인터록을 무시하므로 설비가 움직이지 않는 상태와 주변 인원을 먼저 확인하고, 점검이 끝나면 반드시 해제합니다. |
| 다운로드·업로드 / Download, Upload | PC의 프로젝트를 PLC로 내려보내는 작업과 PLC의 프로그램을 PC로 올리는 작업입니다. PLC에 다운로드한 것과 저장소의 커밋이 같은지 확인하는 절차가 버전 관리의 핵심입니다. |
| 텍스트 내보내기 / Text export | 바이너리 프로젝트를 XML·텍스트로 내보내 Git에서 diff할 수 있게 하는 방식입니다. Rockwell의 기본 `.ACD`는 바이너리라 L5X로 내보내고, Siemens는 SIMATIC SD 형식과 Version Control Interface(VCI)를 씁니다. |
| 단위 테스트 / Unit test | 기능 블록 하나에 입력을 넣고 출력을 확인하는 테스트입니다. 재사용 FB와 상태 머신 전이·타임아웃부터 시작하며 TcUnit, CODESYS Test Manager, AxUnit 같은 도구가 있습니다. |
| PLC 시뮬레이션 / PLC simulation | 실제 CPU 없이 PC에서 PLC 프로그램을 실행하는 것입니다. 시뮬레이터가 실제 CPU의 타이밍·통신·안전 기능을 모두 같게 재현하지는 않으므로 지원 범위를 확인합니다. |
| 가상 시운전 / Virtual commissioning | 시뮬레이션 PLC에 설비 모델을 연결해 시퀀스를 검증하는 단계입니다. 센서 지연, 실린더 속도, 센서 미입력 같은 고장 상황을 모델에 넣지 않으면 잘못된 확신을 줍니다. |
| PLC용 CI/CD | 커밋마다 빌드·정적 분석·단위 테스트를 자동으로 돌리는 흐름입니다. 빌드 서버에 벤더 도구와 라이선스가 필요하고, 운전 중인 설비로 자동 배포하지 않으며 다운로드는 사람이 승인해서 합니다. |
| 엔지니어링 코파일럿 / Engineering copilot | 엔지니어링 도구 안에서 코드 생성·설명·문서화를 돕는 생성형 AI입니다. 생성된 코드는 사람이 읽고 테스트·시뮬레이션을 통과한 뒤에만 다운로드하며, 안전 관련 코드에는 그대로 쓰지 않습니다. |
